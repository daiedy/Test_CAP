# docs-toolchain: plan

Date: 2026-10-14. Status: approved. Gate mode: semi-autonomous.

Shape (ADR-0018): one criterion per line under "Acceptance criteria", table rows only under "Steps"; explanations belong in `CONTEXT.md` or `research/`. `node scripts/check-feature-docs.mjs docs-toolchain` verifies the shape at the phase 1 gate.

Contract rule: a step that changes the OData model (`db/*.cds`, `srv/**/*.cds`, `app/*/annotations/*.cds`) schedules `npx vitest -u` and `cds compile '*' --to edmx-v4 -s CatalogService -l en > app/products/webapp/localService/metadata.xml` in the same phase, never in a later one; the sync test in `test/metadata.test.js` turns red at that phase's gate otherwise (PATTERNS "OData contract"). Figures: `metadata.xml` 1591 lines and 4 `Core.Description` today; 1604 and 11 after the `cdsc.docs` switch alone; about 1670 and 67 after step 2 (scratch set of 10 projection and 51 element doc comments plus the service title and version, `research/docs-facts.md` section 2; the actual figure replaces the estimate in the gate record). Step 2 is the only phase that changes the model. Precondition for steps 3 and 4: the session is started with `PIPELINE_ALLOW_PROTECTED=1` (new dev dependencies change `package-lock.json`; step 4 edits `scripts/lib/**`, `.claude/rules/**`, `.claude/skills/**`).

## Decisions that require an ADR
- ADR-0029 "Documentation toolchain" (accepted by the user on 2026-10-14, `docs/decisions/ADR-0029-docs-toolchain.md`): decision 1 `cds.cdsc.docs: true` in `package.json` as the single switch; decision 2 the CDS doc comment as the only description mechanism, placed per artefact kind (`db/` developer note; projection and elements in `srv/annotations/<Entity>.cds`; service, action, type, singleton at their definitions; `//` for developer notes), never `@description`/`@Core.Description` in project CDS; decision 3 English literals and the service header `@protocol: 'odata-v4'`, `@title`, `@Core.SchemaVersion` (invariant 7 exception for API documentation); decision 4 the OpenAPI document `docs/api/CatalogService.openapi3.json` written by `npm run docs:registry` and `npm run docs:api`, stamped with `info.x-sources`, checked by `check-docs-fresh.mjs`; decision 5 the JSDoc page `docs/registry/JSDOC.md` from an in-house extractor in `gen-registry.mjs`; decision 6 `cds-swagger-ui-express` as a dev dependency; decision 7 the jsdoc rule set, its scopes and gates (root `lint:js` in CI and `/test-all`, `checkUi5` runs the app ESLint); decision 8 descriptions in `DOMAIN-MODEL.md`.
- No ADR for `cds-swagger-ui-express` itself beyond decision 6 (a dev-time plugin, no runtime integration) or for the new `lint:js` scripts (commands, PATTERNS "Run for development" style).

## Risks
- `cds.test()` loads plugins, so the Swagger middleware starts in every backend test run: measured at the step 3 gate; if `npm test` grows by 2 seconds or more, the `test` script sets `CDS_SWAGGER=false` (the plugin's documented switch) and the Swagger test starts its own server with the variable unset.
- `/$api-docs/**` is served without authentication in development (mounted on the Express app, not under the service): the OpenAPI document exposes the model shape to an anonymous caller on a developer machine only; the package is a dev dependency and absent from a production install (`npm ci --omit=dev`); no CI probe or README example changes (the rule on unauthenticated callers concerns changed endpoints; this is a new dev-only one, listed here).
- The converter puts a projection's `Core.Description` into the OpenAPI schema `title` and a tag's `description`, and `Core.LongDescription` into the schema `description`: a long doc comment becomes an unwieldy title, hence the one-sentence rule; the reviewer checks it.
- The tag of the bound action `importProducts` reads "Products.import Products" (the converter humanizes the `@title` key before localization, `@cap-js/openapi` 1.6.0): cosmetic in Swagger UI, documented in the research file and the SUMMARY; the user posts an upstream issue to `cap-js/openapi` whose text the orchestrator prepares (user decision D5, 2026-10-25).
- `@cap-js/openapi` is pinned to 1.6.0 (ADR-0029 amendment A, user decision 2026-10-25) because 1.7.0 answers 500 on the Swagger document of a draft-enabled service: the pin is dropped when a fixed release exists; a Dependabot bump to 1.7.x arrives as its own PR (`exclude-patterns` under the `sap-cap` group, ADR-0029 amendment G) and turns `test/api-docs.test.js` "serves the Swagger UI and its OpenAPI document in development" red for that PR only, the intended guard, while the CAP group updates as before; the defect is reported upstream by the user (D5).
- `eslint-plugin-jsdoc` 65.3.2 declares `engines` `node ^22.22.2 || >=24.15.0`; the project runs 22.23.2 (STACK); an older Node 22 prints an npm engine warning.
- Two ESLint installations (root 10.11, app 10.x) each get their own `eslint-plugin-jsdoc`; Dependabot bumps them separately; the rule set is written twice by necessity (two configs) and the reviewer compares the two blocks.
- `docs/api/**` is not a protected path: a hand edit that keeps the stamp passes `check-docs-fresh.mjs` until the next regeneration; `test/api-docs.test.js` byte-compares with a fresh compile at every `npm test`, which closes the gap at the Stop gate and in CI.
