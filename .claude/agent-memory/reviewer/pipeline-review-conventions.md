The review step always runs before `docs-keeper` (step numbers differ per plan: 16/17 in `categories-code-list`, 10/11 in `products-draft-edit`, 8/9 in `products-draft-marker`). At review time these are expected, not findings: missing `SUMMARY.md`, unrefreshed or uncommitted `docs/registry/*`, PATTERNS/TESTING/templates not yet updated, unticked PLAN and ADR consequence checkboxes, missing LESSONS entries, stale "Next steps" wording in STATE. `ui-verifier` may run in parallel (runs 1-2, so `VERIFICATION.md` can be absent while `screenshots/` exists) or as its own phase before the reviewer (run 3: `VERIFICATION.md` present with a verdict, still uncommitted). UI runner output (`ui5-test-runner`) is gitignored (`app/products/report/`), so the OPA "passed" claim rests on agent reports plus `VERIFICATION.md`.

Since the second run the PLAN carries an explicit reviewer checklist in the "Review" step row; the orchestrator's task message repeats it with numbered items and asks for evidence per item (command output quoted). Work through that list first, then the generic protocol.

Since the third run the review phase is split into several `reviewer` invocations, one per lens (e.g. "plan conformance, patterns and layers", "documentation truth and language discipline"); each lens gets the same diff but a different numbered work list. Consequence for severity: a defect whose fixer is `docs-keeper` in the next phase must be `non-blocking`, because marking it blocking would stop the review phase from closing and `docs-keeper` cannot run before it closes. Reserve `blocking` for defects in the committed code/annotations or a language-rule violation, and put every phase-6 item in the findings list anyway so nothing is lost.

Since the third run the orchestrator also spawns a `reviewer` to *refute* one other reviewer's finding ("default to refuted unless you can positively establish it must block"). The decisive check in this project is the PLAN's split between its prose acceptance criterion and its normative code block: `PLAN.md` "Acceptance criteria" describes what the artifact should contain, while "Details for the developers" pastes the exact code the developer must write. When those two disagree (2026-09-09: criterion asked for an *ordered* `Term="Common.SemanticKey"` … `<PropertyPath>name</PropertyPath>` assertion, the code block gave two independent `toContain` calls, and the implemented test was byte-identical to the code block), the implementer who followed the code block is not at fault - deviating from an approved plan silently is the forbidden move (protocol section 9). Diff the plan block against the implementation (`sed -n` both ranges into the scratchpad, `diff`) before accepting such a finding, and check whether a behavioral test elsewhere in the same feature already covers the gap the finding claims is unguarded.

**Why:** First run (2026-09-07): the orchestrator said not to flag registry drift; VERIFICATION.md was absent at review time. Second run (same day): same hand-off shape, plus explicit "do not start or stop dev servers" because ui-verifier owns :4004. Third run (2026-09-09, `products-draft-marker`): the hand-off lists the deliberately uncommitted phase-6 files by name, pre-supplies the measured gate numbers ("do not re-derive"), assigns a lens ("plan conformance, patterns and layers"), and requires the answer through the StructuredOutput tool instead of prose.

**How to apply:** Report registry/STATE/PATTERNS gaps as "for docs-keeper", not blocking. Re-run yourself: `npm run lint`, `npm test`, `node scripts/check-docs-fresh.mjs`, `npx prettier --check` on changed test files, `diff <(cds compile '*' --to edmx-v4 -s CatalogService -l en) app/products/webapp/localService/metadata.xml`, and `ui5lint` in `app/products` (cheap, ~10 s). In zsh quote grep globs (`--include='*.cds'`, `ls srv/*.js` fails with "no matches found" when empty, which is the wanted evidence). Do not write a REVIEW.md unless the plan lists it as a step artifact; return findings in the message. Since run 5 (2026-09-25, `products-rating-column`) the Review row does list `REVIEW.md`, the hand-off pre-lists "known points to judge" (plan-vs-actual figures, ids changed by test-ui, pre-existing lint warnings, out-of-scope chores, verifier observations) and asks for blocking/non-blocking plus owning agent per finding. Check the *main* version before blaming a formatting or lint failure on the branch (`git show main:<file>` into a temp copy inside the project so prettier picks up the config).

Run 6 (2026-09-25, `products-rating-filter`): the hand-off asked for `REVIEW.md` written first and grown as you go. `npm run test:ui` is cheap enough to re-run yourself (~2.5 min: start `npx cds serve --in-memory --port 4004` in the background, poll with curl, run, then `pkill -f 'serve --in-memory --port 4004'`; macOS has no `timeout`). Prettier is enforced by no gate (`ui5lint`, `lint:js` ignore it), so `npx prettier --list-different` on new files regularly finds unformatted new JS; compare against `main` copies because several old test files were never formatted. BSD grep has no `-P`: scan Cyrillic with `perl -CSD -ne '/[\x{0400}-\x{04FF}]/'`.

Run 7 (2026-09-25, `products-excel-upload`): the review hit the orchestrator's 50-turn limit before REVIEW.md held any finding. Write each confirmed finding into REVIEW.md immediately (Edit append), keep reads targeted (`grep -n`, `sed -n`), and run slow evidence (OPA rerun ~2.5 min) in the background while reviewing. cds 10 source facts worth re-using: positional `req.error(400,'KEY')` leaves `400` in `details[].code` (`lib/req/response.js` + `normalized()` in `lib/srv/protocols/http.js`), and `sap-messages` is never localized (`ODataAdapter.sap_messages4`).

Run 8 (2026-10-02, `pipeline-metrics`, a pipeline-only feature, ~6.5K diff lines): I hit the turn limit again while REVIEW.md was still a skeleton, because I read whole 1,400-line modules first. Next time, after reading PLAN/CONTEXT/definitions, write each finding into REVIEW.md the moment it is confirmed, and read code with `grep -n` plus narrow `awk 'NR>=a && NR<=b'` ranges. REVIEW.md is machine-read: `reviewCounts()` in `scripts/lib/pipeline-metrics.mjs` counts the top-level `- ` items under `## Blocking`/`## Important`/`## Minor` (it skips `- none`), and those counts go into the committed `docs/metrics/history.jsonl`. So keep one top-level bullet per finding and put no list items for anything else under those headings. CLI output pasted into REVIEW.md must be English: run with `PIPELINE_LANG=en`, because the PostToolUse hook flags the ru card. zsh has no `PIPESTATUS`, so use `echo $?` on unpiped commands. Coordinator messages can bring user decisions mid-review (R2-F7 was decided while I worked); record those as findings with the decided fix, not as open questions.

Run 9 (2026-10-04, `pipeline-metrics` re-review after the fix batch `127be1f`): the hand-off scoped the work to the fixed items only, with a 25-call budget. The approach that fitted the budget: one `git show <sha> -- <files> | grep -v '^ '` per file group, run the four requested checks in one background call into the scratchpad, and probe untested behaviour with a `node --input-type=module -e` import instead of a mutation, because a reviewer edits nothing. Append `## Re-review <date>` with `###` subheadings: `sections()` (`doc-shapes.mjs`) splits only on `## `, so `reviewCounts()` keeps counting the original findings. Check that with `reviewCounts(readFileSync(REVIEW.md))` after writing. Typical leftover after a fix batch: a requested test that was never added (look for the new i18n key in `test/`), and a header comment in a protected hook file that still states the old rule. In zsh `echo ===` fails (`== not found`); use `echo "-- x"`.

Run 10 (2026-10-07, `pipeline-state-hygiene`, pipeline-only, ~1.3K diff lines): fitted in ~25 calls by writing the REVIEW.md skeleton first, running all gates in one background call, and writing the full file once the findings were confirmed. To prove a PreToolUse guard still denies a path, copy `scripts/` into a scratch dir with `git init` and pipe JSON into `protect-files.mjs` / `protect-files-bash.mjs` there (metrics land in the scratch `.pipeline/`, not the real one); `unset PIPELINE_ALLOW_PROTECTED` first, because sessions that write `scripts/**` carry it and the guards then print nothing. `protect-files-bash` answers `ask`, not `deny`, for every protected path by design. When the hand-off asks to "judge implementer choices", answer each in "Checked and in order" with the ADR clause that decides it, and raise a Minor only for what is concretely missing (e.g. no test pins the accepted reading).

Run 11 (2026-10-09, `catalog-hygiene`, a small model-hygiene feature, ~360 diff lines): single reviewer invocation with the PLAN step 9 checklist repeated in the hand-off, and `REVIEW.md` required. ~30 calls were enough: skeleton first, all gates in one background call (lint, test, ui5lint, docs-fresh, prettier, EDMX diff, `check-feature-docs.mjs`), then the OPA rerun on port 4013 in the background (took ~5 min this time, not 2.5). Where to look for real defects in such features: (1) the uncommitted `VERIFICATION.md` against `templates/feature/VERIFICATION.md`, because `ui-verifier` leaves sections half-filled (here a trailing `pending` in "Browser console" and no `## Automated tests`), (2) the PLAN's own docs-keeper checks: a "grep finds only X" check is often unattainable because an in-place ADR amendment and older SUMMARY quotes keep the historical string, and (3) the architect's `research` worklist of "documents that carry the old facts", whose grep can miss hits (run the grep yourself). Ticked PLAN criteria that cite stale line numbers after a comment grew are not findings: tests assert by value.

Run 12 (2026-10-09, `products-subcategories`, ~2.1K diff lines incl. screenshots): the session runs in a git worktree whose Bash guard refuses compound commands that mix `git`/`npx`/`perl`/`xargs` with loops, `$(...)` or `mkdir` in one line ("too complex to verify"): run each git/npx command plainly, write scan scripts (e.g. a Cyrillic scan over a file list) as a `.mjs` in the scratch dir and run them with `node`. Reading `docs/registry/*` through `grep` in Bash trips the protected-path PreToolUse hook; use the Read tool. I hit the turn limit once more before "Checked and in order" was written: write that section (with the gate outputs) right after the gates return, before hunting more findings. Design-prediction defects are worth checking: SCREENS predicted pop-in order, the verifier measured another one, and an existing OPA journey had to add Show Details. The re-review of that run (fix batch uncommitted, ~15-turn budget) fitted in ~14 calls: `git status` + one `git diff` of the fixed files, gates in one background call, `git diff -w` to prove a large reformat diff is whitespace only, an OPA rerun on :4013 in the background while appending `## Re-review`, then `reviewCounts()` to confirm the counts are unchanged.
