## Decisions that require an ADR
- ADR-0025 "Field editable only when another field is filled (dynamic field control)", accepted 2026-10-10; this feature is its first application, with the `7` branch that ADR-0025 point 4 requires on a `@mandatory` element.
- `@mandatory` on `subcategory` follows the existing "Mandatory field" row; the import column follows ADR-0021 and the ADR-0024 consequence on project message keys; no further ADR.

## Risks
- The disabled and required rendering of a dynamic `FieldControl` is source-read from UI5 1.153.0 (`FieldControlHelper`, `UIFormatters.getEditMode`), not measured in a browser; step 6 asserts the edit mode and the required state, step 7 takes the screenshots.
- Emptying the mandatory Category dropdown may not reach the server as `PATCH category_code: null` (UI5 type or FE required check); step 6 measures it; if the UI cannot empty it, "Emptying the category empties and disables the subcategory" is dropped, the case stays covered by the step 3 draft test, the phase 3 UI gate becomes 51 and the deviation goes into `SUMMARY.md`.
- After a category change the subcategory is empty and required; the reset writes no draft message (measured), so the user learns of a forgotten subcategory from the required marker and, at Save, from the `ASSERT_MANDATORY` message on `in/subcategory_code`; step 7 records which one Fiori Elements shows first.
- A disabled input is skipped by Tab; screen readers in browse mode still read it with its label and an "unavailable" state; step 7 checks keyboard reachability once enabled.
- D7 = A changes the workbook contract: a workbook without a `subcategory` column is rejected as a whole (`PRODUCTS_IMPORT_MISSING_COLUMN`); `README.md` documents the column in the same phase; nothing else reads the workbook.
- Every existing test that creates a product without a subcategory turns red at phase 2 until `newProduct` carries one; steps 2 and 3 run in the same phase, the gate is the green suite.
- Contract figures per phase: phase 2 875 (+1), phase 3 884 (+10 -1 against phase 2); phase 4 onwards does not change `metadata.xml`.
- Between the category `PATCH` and the side-effect read the old subcategory is visible for a moment while the field is already enabled; Fiori Elements sends both in one `$batch`; step 7 records it.
- No change to what any endpoint answers to an unauthenticated caller (`@requires`, `@restrict` untouched): the CI readiness probe in `.github/workflows/ci.yml`, the `run-app` and `test-all` smoke curls, the `ui-verifier` server check and README examples need no update for authentication.
- Mock mode serves the regenerated `metadata.xml`; all 15 mock products have a category and a subcategory, so no fixture change; not part of a gate.

A (recommended): the workbook gets a mandatory `subcategory` column (subcategory code), a row with an empty one is reported for its row, a subcategory of another category is reported for its row instead of failing the whole file (`validationErrors` maps `PRODUCTS_SUBCATEGORY_MISMATCH`, closing the #8 open debt), `README.md` and the fixtures follow; the rule is the same on every path. B: no `@mandatory`; Subcategory is mandatory only in the Fiori draft flow (`FieldControl` 7 plus a `before('SAVE', Products.drafts)` handler that rejects an empty subcategory); the import and direct API writes keep an optional subcategory; two rules for one field and a handler where an annotation exists, not recommended.
