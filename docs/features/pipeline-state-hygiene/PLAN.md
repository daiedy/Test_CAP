## Decisions that require an ADR
- ADR-0023 `docs/decisions/ADR-0023-pipeline-state-hygiene.md` (proposed): (1) "spec in progress" is derived from `docs/features/<name>/` holding `PLAN.md` or `CONTEXT.md` for an open issue without `spec-ready`, no label and no STATE value, an amendment of the ADR-0019 recommendation order; (2) the STATE drift rule (branch mismatch; `Last commit:` unknown, not an ancestor, or more than 1 first-parent commit behind) and its delivery: SessionStart briefing line plus a Stop `additionalContext` feedback once per drift key, never a block; (3) `.claude/worktrees/` is gitignored and exempt from the git-based protected audit only, the PreToolUse guards keep denying writes into it. The PATTERNS row "Advisory from a Stop hook" follows from decision 2.

## Risks
- Each Stop feedback costs one model continuation; the drift key limits it to once per distinct drift, and SessionStart records the key so a drift already shown at start does not repeat at the first Stop. Detection: the sandbox test pins "once"; the live check of step 6 counts the feedback lines.
- A `git pull` of upstream commits on `main` makes STATE stale by design and triggers the warning; that is correct (STATE is stale) and costs one continuation.
- Stop `additionalContext` is a documented but recent field (Claude Code 2.1.289 here): if a version ignores it, the feedback is silently lost, not harmful. Detection: the live check of step 6; `upstream-watcher` notes Claude Code hook changes.
- The existing `hooks-metrics.test.js` sandbox carries `Last commit: 0000000 init`, which is a drift: its exit codes and records must stay as asserted; the extraction in step 4 keeps the file's 8 tests and their expectations byte-identical.
- A subagent with `isolation: "worktree"` started from the main session would have its edits denied by `protect-files.mjs` (the path is under `.claude/**` relative to the main root); no pipeline agent uses it today. Out of scope, named in ADR-0023 consequences.
- The briefing reads the local folder only: a spec drafted in another clone or worktree stays invisible; acceptable, the drafts live where the session runs.
- An abandoned draft folder keeps the review recommendation on top until the folder is deleted or the plan approved; the recommendation text names the folder.

## Open questions
None. The user approved the plan on 2026-10-06 with the recommended answer to each question below; the decisions are recorded in `CONTEXT.md` "User decisions" and ADR-0023 (accepted).

1. STATE drift (issue question 1): decided as recommended, a warning only, the SessionStart briefing line plus a Stop `additionalContext` feedback once per drift that never exits 2 (plain stdout of a Stop hook reaches no one but the debug log, `research/state-drift.md` section 2); alternatives: a blocking Stop gate while `Last commit:` is stale (blocks read-only turns and every `git pull` until STATE is edited), or SessionStart only (would have missed the #7 incident, where the drift appeared mid-session).
2. "Spec in progress" in STATE (issue question 2): decided as recommended, derived from the folder only, no `Phase: spec` value (`/spec` writes no STATE line by ADR-0019, and the ADR-0022 phase parser takes the first integer of `Phase:`); alternative: `/spec` writes `Phase: spec`, which amends ADR-0018 and ADR-0019 and grows `.claude/skills/spec/SKILL.md`.
3. Worktrees (issue question 3): decided as recommended, `.gitignore` plus an exemption of `.claude/worktrees/**` in the git-based audit (`protectedWriteHit()`) only, and the block message for an untracked entry without the `git checkout --` advice; no `git worktree list` recognition (the `.gitignore` line removes them from `git status`, measured in `research/state-drift.md` section 3). This deviates from the issue's literal "`PROTECTED_EXCEPTIONS`", which would also open the Edit/Write and Bash guards and let the main session write into a parallel session's checkout; alternatives: the literal `PROTECTED_EXCEPTIONS` entry, or additionally naming registered worktrees from `git worktree list --porcelain`.
4. Prompt rule (issue scope hint): decided as recommended, no new line in `.claude/skills/feature/SKILL.md`, the `project-protocol` skill or `.claude/rules/pipeline-config.md`, because the hook texts carry the instruction at the moment it matters and `test/prompt-budget.json` stays as recorded; the worktree rule is documented in the `.gitignore` comment and ADR-0023; alternative: one line each in `feature/SKILL.md` (a `!` git command that moves HEAD is followed by a `## Now` update) and `pipeline-config.md`, with `node scripts/prompt-budget.mjs --record` and a CHANGELOG line as part of step 8.
