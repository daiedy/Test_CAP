## Important
- `srv/catalog-service.js:83-84` (`rejectImport`) uses the object form `req.error({ status: 400, code, args })`, while PATTERNS "Business logic error" (`req.reject(400, 'KEY', [args])`), CONVENTIONS line 69, `.claude/rules/srv-handlers.md` "Errors" and ADR-0021 decision 4 (`req.error(400, 'PRODUCTS_IMPORT_ROW_INVALID', [...])`) show the positional form. The deviation is technically forced and acceptable: in cds 10.0.6 `prepareError` (`node_modules/@sap/cds/lib/req/response.js:21-27`) turns `req.error(400, 'KEY', args)` into `{ code: 400, message: 'KEY', args }`, and `normalized()` (`lib/srv/protocols/http.js:123-131`) replaces `code` by the key only when `e.code == e.status`; that holds for the top-level error of `req.reject` (status inferred as 400) but not for a collected detail (no `status`), so every `details[].code` would stay `400` and the tests that assert the `PRODUCTS_IMPORT_*` codes could not pass. Same API, no second mechanism. → `docs-keeper` (phase 6): extend the PATTERNS row "Business logic error" with "several collected messages: `req.error({ status, code: 'KEY', args })` per message; the positional form leaves the status in `details[].code`", align CONVENTIONS line 69, add a LESSONS entry; `architect`: a one-line note under ADR-0021 decision 4 that the implementation uses the object form; user: `.claude/rules/srv-handlers.md` "Errors" (protected file).
- `srv/catalog-service.js:63-70`: the success message is resolved by hand, `cds.i18n.messages.at('PRODUCTS_IMPORT_DONE', req.locale, args)` passed as `message` of `req.info({ code, message, args })`. Verified as necessary: `ODataAdapter.sap_messages4` (`node_modules/@sap/cds/libx/odata/ODataAdapter.js:110-117`) calls `normalized()`, which resolves the key in `i18n.default_language`, and never `localized()`; the code comment names the gap correctly; `cds.i18n.messages.at(key, locale, args)` is the documented API (capire "cds.i18n", via `cds-mcp`); pinned by the test "importProducts reports success in Russian". Acceptable. What is missing is the pattern: PATTERNS has no row for a success message of an action. → `docs-keeper`: add the success-message form to the "Business logic error" row (or a row "Success message of an action") and a LESSONS entry "Pending upstream @sap/cds: `req.info` keys are not localized in `sap-messages`".
