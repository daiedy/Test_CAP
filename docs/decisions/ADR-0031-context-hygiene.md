# ADR-0031: Context hygiene: role briefs from marked feature documents, a soft gate on repeated reads, relays without cuts, a context card

Date: 2026-11-09, amended 2026-11-10 (decision 5 widened, decision 7 added at the plan gate). Status: proposed (feature `context-hygiene`; decision by the user pending).
<!-- On acceptance replace the whole Status sentence with the accepted form; never append to the proposed one. -->

## Context

Issue #44 asks to keep every agent's context free of stale and duplicated material, for the quality of its reasoning; tokens are a side benefit. Nothing may be cut by a character or line cap. ADR-0018 already fixes the principles (the unit of a cut is a section or a file, the budget lives with the writer, a cap is visible, numbers come from measurement), but it stops at the documents: every feature agent still reads `PLAN.md` and `CONTEXT.md` whole, the hooks that relay tool output cut it by lines and characters, and nothing measures what a context holds.

Measured on the `/feature` run of #28 (21 subagent launches, 2026-11-09, `docs/features/context-hygiene/research/context-measurements.md`): tool results are 42% of a context by characters (2,597.4K); the feature documents and the feature's own ADR are 19.5% of them (`PLAN.md` reached 7 agents, ADR-0030 reached 10); shell prints and searches (`sed`, `cat`, `grep`) are 53%; the check commands are 3.4%, and a green `npm test` prints 739 bytes; a repeated delivery of a file to the same agent is at most 7.6% by any route, 2.2% through `Read`, and no whole-file `Read` was repeated. The hooks cut what they relay: the Stop gate prints the last 40 lines of a red test run, `lintNote()` the first 20 findings and SubagentStop the first 30 errors, each without a marker. PATTERNS has no row for a role brief, a read gate or a relay of check output.

## Decision

Seven parts.

1. **Markers in the feature documents.** In `PLAN.md` every criterion sits under `### Phase <N>: <label>` (the `/feature` phase) or `### Every phase`, and a Steps `Phase` cell starts with `<N>: `. In `CONTEXT.md` a section is for every reader, or is split into `### <Readers>: <title>` subsections with `Readers` from `All`, `Backend`, `UI`. `SCREENS.md` gets no marker; its template section names select. `planShapeErrors()` and `contextShapeErrors()` check the markers; there is no legacy switch, the two folders that hold a `PLAN.md` are migrated.
2. **A role brief handed at start.** `briefFor()` in `scripts/lib/feature-brief.mjs` builds, for an agent type and a phase, its own step rows, the criteria of its phase, the shared and role sections of `CONTEXT.md`, a reading list (SCREENS sections, the feature ADR only for a decision a step row names) and a `## Not included` list of every omitted section with its bytes. The SubagentStart hook writes it to `.pipeline/brief/<agent-type>-<phase>.md` and hands it whole when it fits the hook output limit, otherwise the path. Implementers, testers, `ui-verifier` and `docs-keeper` get a brief; `reviewer`, `architect` and `ux-designer` read whole. The largest brief per role group is pinned in `test/context-budget.json` and checked by `scripts/check-feature-docs.mjs`. The orchestrator's delegation message keeps the feature name, step numbers, gate mode, turn budget and what changed since approval.
3. **A soft gate on repeated reads.** A PreToolUse hook on `Read` keeps a ledger per session and agent id of whole-file reads with the content hash. A second whole read of the same file with the same hash is denied once with the reason; the retry passes. The same single deny points an agent that received a brief to it when it opens `PLAN.md` or `CONTEXT.md` whole. Partial reads, changed files and errors always pass; a compaction of the main thread resets its entries.
4. **Relays without cuts.** A hook that relays tool output prints it whole, or, above the hook output limit, a summary by structure (counts per rule, the failed test names) with the path of the whole under `.pipeline/logs/`. No head, no tail, no character cap. The check commands stay as they are: one line per finding is already the writer's short form. Reports cite the verdict a command printed and the log path, never "last lines".
5. **A context card.** The transcript parser keeps, as sizes and identifiers only, the length of each tool result, the path of a `Read`, the program class of a Bash command and the length of hook context. `scripts/metrics.mjs` prints per launch the startup and peak context, the number of compactions next to the peak, tool-result characters by tool, repeat-read characters, brief characters and the largest results, and per agent type the launches, the resumes (a `SendMessage` delivery) and the compactions as three separate figures (D14-D18 in `docs/metrics/definitions.md`; the record kind that identifies a compaction is measured on the #28 session and named there), and the history line carries the totals.
6. **Probe before code.** Every hook behaviour the design depends on is proved in a temp project outside the repository before a dependent file is written, and each has a fallback (`CONTEXT.md` "Probe facts"): the brief by path in the delegation message, pointer mode only, the gate on the main thread only, a note instead of a deny, a note-only resume gate with the ratchet.
7. **Rework by fresh launch.** A rework after a report is by default a new agent of the owning type: it gets its brief from the SubagentStart hook, the orchestrator's defect list and the path of the previous report. A resume via `SendMessage` is used only when the agent stopped mid-step and its deliverable on disk is behind its progress. Reason, from the user and the #28 measurement: a resumed agent carries every stale tool result of its first run (the architect of this very specification was resumed at about 380K tokens for a small edit, the case this decision forbids); the deliverable is on disk by protocol step 10, so nothing is lost by a fresh start; six narrow `docs-keeper` launches peaked at 43-122K tokens against 280K for one long launch. Four levels of enforcement: (1) the rule in the `feature` skill (replacing "the owning agent (or the resumed one)" and "resume it with SendMessage ... relaunch only if it does not answer"), in the `spec` skill (amendments after the plan gate go to a fresh `architect` with the file list and the exact edits) and in protocol section 8; (2) the SubagentStop hook saves `last_assistant_message` whole as `.pipeline/logs/report-<agent-type>-<agent-id>.md`, so the pointer is a path; (3) a PreToolUse hook on `SendMessage` (`scripts/hooks/resume-gate.mjs`) reads the addressee's transcript and denies the resume when it already holds a `SubagentHandback` record, with a reason that names the replacement and the saved report; an agent that stopped at its turn limit without a report passes, as do an unreadable transcript and an unknown addressee; every deny writes a `gate` record with the reason `resume`, and there is no deny-once: a denied resume is replaced, not retried; (4) the context card lists per feature the resumes of agents that had already reported with the context size of each at the resume, and `test/context-budget.json` pins that count at zero, so a rise fails the ratchet at `record` and reaches the retro. The card shows launches, resumes and compactions separately so the cost of a fresh start (one more startup) stays visible.

## Alternatives

| Option | Why rejected |
|---|---|
| Cut tool results with `updatedToolOutput` or a character cap | the user's constraint: a cap silently drops what matters |
| A wrapper `scripts/check.mjs` around every check | the checks are 3.4% of tool-result characters and already short; agents bypass a wrapper with `npx vitest` |
| A custom vitest reporter | a red run measured about 1.6K per failure with a contextual diff; nothing to shorten |
| Read gate as a note only | the note arrives next to the repeated result, so the duplicate still enters the context |
| Read gate as a hard deny within N calls | N is not measured, and no hook can tell whether the earlier result is still in the window after a compaction |
| A gate on Bash prints (`cat`, `sed`) | needs a shell parser in a hook; a `sed -n` range is a precise read; the card shows the route instead |
| Per-line phase tags on criteria | a tag is a line filter; a subsection is a unit a reader can also open by hand |
| Hidden HTML comments as reader markers | invisible to the human who reviews the plan |
| The orchestrator pastes the slice into the delegation message | restates plan content by hand in every launch and depends on compliance |
| `autoCompactWindow` for subagents | compaction is a lossy summary; decided again with the card after `/feature #10`, which now shows the compactions per launch |
| Resume the owning agent for a rework (SendMessage first, relaunch only when it does not answer) | the resumed context holds every stale result of the first run; the deliverable is on disk, so a fresh agent with the brief, the defect list and the report path loses nothing and starts at 21.5K-32.1K tokens instead of the previous peak |
| The rework rule as prompt text only | the architect of this specification was resumed at about 380K tokens against the rule's intent; a gate and a zero ratchet make the exception visible |
| The orchestrator pastes the previous report into the rework message | restates a report by hand and competes with the brief for the delegation message; a path to the saved report is shorter and whole |
| Token budgets instead of bytes | no tokenizer in a hook without a dependency (ADR-0018) |

## Consequences

- An implementer of a feature the size of #10 reads an estimated 53-62% of the two documents; the measured sizes are recorded at the migration.
- A plan written from the template is readable by `planAssignments()`, so plan-aware rework no longer falls back silently.
- The architect writes markers; a wrong phase hides a criterion from its implementer, which the shape rule, the tester's brief and the reviewer catch.
- New: `scripts/lib/feature-brief.mjs`, `scripts/feature-brief.mjs`, `scripts/hooks/read-gate.mjs`, `scripts/lib/read-ledger.mjs`, `scripts/hooks/resume-gate.mjs`, `test/feature-brief.test.js`, `test/hooks-context.test.js`, `test/context-budget.json`, `.pipeline/brief/`, `.pipeline/logs/` (check logs and `report-<agent-type>-<agent-id>.md`), `.pipeline/read-ledger-<session>.jsonl`.
- Changed: `subagent-start.mjs` now prints (reverses its "never prints" note), `stop-gate.mjs`, `subagent-stop.mjs` (also saves the report), `pre-compact.mjs`, `session-start.mjs`, `hook-utils.mjs`, `file-checks.mjs`, `doc-shapes.mjs`, `transcript-usage.mjs`, `pipeline-metrics.mjs`, `metrics-log.mjs` (`GATE_REASONS` `reread`, `brief`, `resume`), `.claude/settings.json` (matchers `Read` and `SendMessage`), the protocol (section 2 step 1, sections 6 and 8), the `feature`, `spec` and `test-all` skills, nine agent prompts, the three feature templates; `test/prompt-budget.json` re-recorded.
- The field list of ADR-0022 (`docs/metrics/definitions.md` section 1) grows by sizes, tool-use ids, file paths, a program class, the compaction record kind and the `SubagentHandback` and `coordinator` delivery markers; still no prompt, command text or tool output.
- PATTERNS gains the rows "Feature brief", "Repeated read gate", "Check output relay" and "Rework by fresh launch"; ADR-0018 gets the amendment of the same date.
- A rework costs one more startup (21.5K-32.1K tokens on #28) instead of a resume; the card shows launches, resumes and compactions apart, so the trade is measured, not assumed.
- Harder: every `Read` and every `SendMessage` starts one more hook process; a Claude Code release can change a hook field or the subagent transcript path, which the probe script re-checks.
