# Products Excel upload: plan

Date: 2026-09-25. Status: approved (user, 2026-09-25). Gate mode: semi-autonomous.

Shape (ADR-0018): one criterion per line under "Acceptance criteria", table rows only under "Steps"; explanations belong in `CONTEXT.md` or `research/`. `node scripts/check-feature-docs.mjs <name>` verifies the shape at the phase 1 gate.

Contract rule: a step that changes the OData model (`db/*.cds`, `srv/**/*.cds`, `app/*/annotations/*.cds`) schedules `npx vitest -u` and `cds compile '*' --to edmx-v4 -s CatalogService -l en > app/products/webapp/localService/metadata.xml` in the same phase, never in a later one; the sync test in `test/metadata.test.js` turns red at that phase's gate otherwise (PATTERNS "OData contract").

This plan follows the user's answers of 2026-09-25 (CONTEXT "User decisions" 1-15; ADR-0021 accepted). Button label "Import from Excel" (user decision 11; SCREENS.md still says "Import" for `Products.action.import`, the user's label wins). Follow-up for `/backlog`, not created by this feature: an in-app download of a sample workbook (user decision 4). **The OData contract changes in two phases**: phase 2 (action `importProducts`, type `ProductsImportFile`, their annotations) and phase 3 (`UI.DataFieldForAction` with `UI.Hidden` in `UI.LineItem`); each phase regenerates the snapshot and `metadata.xml` and names its own EDMX line delta in its gate report (`git diff --numstat` of `app/products/webapp/localService/metadata.xml` against the previous phase's commit); no figure is predicted here. Baselines on `main` (2026-09-25): `npm test` 69 tests in 7 files, `npm run test:ui` 28 `opaTest`s. No endpoint changes what it answers to an unauthenticated caller (CONTEXT "Affected entities and services"), so no external caller is updated.

## Acceptance criteria
- [ ] An editor posting the valid fixture `test/fixtures/products-import-valid.xlsx` (3 rows) to `POST /odata/v4/catalog/Products/CatalogService.importProducts` gets 200 with value 3, and the 3 products exist as active rows with the file's values, verified by `test/catalog-service.test.js` "importProducts creates one active product per row".
- [ ] The created products carry `createdBy` of the caller and no draft exists afterwards (`Products?$filter=IsActiveEntity eq false` empty), verified by `test/catalog-service.test.js` "importProducts creates active products, no drafts".
- [ ] The invalid fixture `test/fixtures/products-import-invalid.xlsx` answers 400 whose first message is `PRODUCTS_IMPORT_NOTHING_IMPORTED`, followed by one message per bad row naming its row number and column (missing `name`, `stock` -1, unknown `category`, non-numeric `price`, duplicate `name`), none with a field `target`, and the product count stays 15, verified by `test/catalog-service.test.js` "importProducts rejects the whole file and reports every bad row".
- [ ] A file with more than 100 bad rows reports all of them (no cap), verified by `test/catalog-service.test.js` "importProducts reports every bad row without a cap".
- [ ] A row whose `name` equals an existing active product (case-insensitive, trimmed) or repeats a name of an earlier row of the file is reported as `PRODUCTS_IMPORT_DUPLICATE_NAME`, verified by `test/catalog-service.test.js` "importProducts reports duplicate names".
- [ ] A file with 1,001 data rows is rejected with `PRODUCTS_IMPORT_TOO_MANY_ROWS` and nothing is created, verified by `test/catalog-service.test.js` "importProducts rejects more than 1000 rows".
- [ ] A payload that is not an xlsx workbook (`PRODUCTS_IMPORT_NOT_XLSX`), a workbook without data rows (`PRODUCTS_IMPORT_EMPTY`) and a header with an unknown column (`PRODUCTS_IMPORT_UNKNOWN_COLUMN`) are rejected, verified by `test/catalog-service.test.js` "importProducts rejects a malformed workbook".
- [ ] A header missing `price` and `category` gives two `PRODUCTS_IMPORT_MISSING_COLUMN` messages, one per column, verified by `test/catalog-service.test.js` "importProducts reports each missing mandatory column".
- [ ] `viewer` gets 403 and an anonymous caller 401 on the action, verified by `test/catalog-service.test.js` "importProducts is forbidden for a viewer" and "importProducts requires authentication".
- [ ] Error and success texts come from `_i18n/messages.properties` and `messages_ru.properties` (`Accept-Language: ru` returns the Russian text), verified by `test/catalog-service.test.js` "importProducts reports errors in Russian".
- [ ] The header mapping (case-insensitive, any order, optional columns missing), numeric coercion, skipping of empty rows and the row numbering of `srv/lib/products-import.js` are covered by `test/products-import.test.js`.
- [ ] `$metadata` contains the action `importProducts` bound to `Collection(CatalogService.Products)` with the parameter `file` of type `CatalogService.ProductsImportFile`, and `UI.LineItem` contains the `UI.DataFieldForAction` with its `UI.Hidden` `$Not` `$Path` expression, verified by `test/metadata.test.js` "importProducts is a collection-bound action shown in the List Report toolbar".
- [ ] `app/products/webapp/localService/metadata.xml` is in sync with the model at the phase 2 and the phase 3 gate, verified by the sync test of `test/metadata.test.js`.
- [ ] Logged in as `alice`, the List Report table toolbar shows the button "Import from Excel", and pressing it opens the action dialog with a file field; Cancel closes it and the table still shows 15 rows, verified by OPA5 "The import button opens the upload dialog" (`ImportProductsJourney.js`).
- [ ] The button label is the `ru` text (U+0418 U+043C U+043F U+043E U+0440 U+0442 U+0020 U+0438 U+0437 U+0020 Excel) and the dialog texts are `ru` in the Russian locale, verified by the `ru` assertion added to `RussianLocaleJourney.js`.
- [ ] `npm test` green with 69 tests plus the ones added in phase 2; `npm run test:ui` green with 28 plus the ones added in phase 3, 0 skipped.
- [ ] `ui-verifier` in a browser: `alice` uploads the valid fixture (chrome-devtools `upload_file`) and sees 18 rows and the success message; uploads the invalid fixture and sees every bad row reported and still 15 rows; `viewer` sees no "Import from Excel" button; `ru` texts; recorded in `VERIFICATION.md`.
- [ ] `npm run lint` clean in the root; `ui5lint` 0 problems and `npm run lint:js` 0 errors in `app/products`; `npm audit --omit=dev` reports no high or critical advisory introduced by `read-excel-file`.
- [ ] ADR-0021 accepted; `PATTERNS.md` has the rows "File upload through an action" and "Bulk create from a file" and the updated rows "Action on a set or without context", "Role-aware UI visibility", "Dependency update", each with this feature as the example.
- [ ] Documentation updated: registry, STATE, CHANGELOG, README (workbook columns), SUMMARY.

## Decisions that require an ADR
- Parsing library, file transport, bulk create on the draft root, all-or-nothing, duplicates, workbook contract and the first added runtime dependency (no PATTERNS rows): `docs/decisions/ADR-0021-products-excel-import.md`, accepted by the user 2026-09-25 after the check that Fiori Elements V4 has no standard file import (research section 3).

## Risks
- Declarative checks may not fire on a service-internal `INSERT` (undocumented); detection: research 5.3 in step 5 before any error mapping is written; reaction: stop and revise ADR-0021, not an imperative copy.
- A `LargeBinary` inside a structured action parameter may arrive in an unexpected shape or as `Edm.Stream` that FE sends differently; detection: research 5.1, 5.2 and 6.3.
- Fiori Elements may not render a file field for a collection-bound action parameter on UI5 1.152 (documented example is instance-bound); detection: research 6.2 in step 8; reaction: the fallback gate of step 8.
- The `$batch` body of a large file may exceed the 100 KB body-parser limit (413); detection: research 5.6 and the 1,000-row test; reaction: the conditional service annotation of step 6.
- Per-row inserts for 1,000 rows may be slow; detection: research 5.7; above 10 s on SQLite in-memory the architect reconsiders the insert strategy before phase 3.
- A second instance of the known `Permissions/isEditor` `$select` TypeError; detection: `ui-verifier` console section; accepted as known noise if identical in shape.
- `UI.Hidden` driven by the singleton may resolve differently from `UI.CreateHidden` (asymmetric failure, CHANGELOG 2026-09-23); detection: research 6.1 and `ui-verifier` as `viewer` and `alice`.
- A test that imports rows leaves them in the in-memory database and shifts later row counts in `test/catalog-service.test.js`; detection: `npm test`; `test-backend` deletes the imported rows at the end of the `describe` or asserts relative counts.
- OPA5 cannot choose a file in the browser's file dialog; the upload itself is covered by the backend tests and `ui-verifier`, OPA5 covers the button, the dialog and Cancel only.
