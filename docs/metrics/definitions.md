## 2. Request and tokens

- D1 **Request** = the set of `assistant` records sharing one `requestId` across the whole scope, in every file that holds them; the scope is a session with its subagent files, or the session set of a feature (#7 main: 287 records, 162 requests; every record has a `requestId`). Usage of a request = per field the **maximum** across all its records in every file; a request id seen in several files counts once. Measured: in the main file all records of a request carry identical usage; in subagent files the usage grows with the stream (opus output summed over first records 126,403, over last records 226,811), and 78% of #7's subagent requests exist only as snapshots with `stop_reason: null`, whose output and thinking stay provisional ([`research/reconciliation.md`](https://github.com/daiedy/Test_CAP/tree/f50d60015972bc2fc020ea056195c4d00552dc6c/docs/features/pipeline-metrics/research/reconciliation.md) H3). Summing every record overcounts (main cache read 52.2M instead of 29.9M). A resumed or forked session copies earlier history into its own file with the same `requestId` and `uuid` (`29ece8c2` repeats 118 of its 119 main-thread requests of `e9ead85a`, and all 66 subagent requests of `e9ead85a` under the same `agent-<id>` file name; all 119 user records of `29ece8c2`'s main file carry a `uuid` of `e9ead85a`, 118 with the same `timestamp`), so counting per file double-counted 25% of `catalog-authorization` ($87.50 instead of $65.39). A copied request belongs to the thread of the first file that holds it in a fixed order (session id, main file before subagent files, then file name); a copy always sits in the same kind of thread (main to main, `agent-<id>` to the same id).
- D2 **Tokens by kind** per request: `input` (uncached), `cacheWrite5m` and `cacheWrite1h` (`cache_creation.ephemeral_*`; their sum equals `cache_creation_input_tokens`), `cacheRead`, `output` (includes thinking; `output_tokens_details.thinking_tokens` is reported as a detail, not priced separately), `model` from `message.model`. `<synthetic>` records (2 in #7, zero usage) are skipped and counted under `skipped`. Measured 5m/1h split in #7: opus 3.52M / 0.65M, sonnet 1.21M / 0 (the prototype priced every write at the 1h rate).
- D3 **Context of a call** = `input + cacheRead + cacheWrite5m + cacheWrite1h`; per agent: average and peak. **Cache hit ratio** = Σ cacheRead / Σ context. Measured #7 (prototype figures): about 130K per call, 95% of token volume is cache read.
- D4 **Cost** = Σ over models and kinds of `tokens × price[model][kind] / 1e6`, prices from `scripts/lib/model-pricing.json` (`recordedAt`, `perMTok`). Seed values, verified against https://platform.claude.com/docs/en/about-claude/pricing (fetched 2026-09-29) and matching `model-pricing.json` ([`research/reconciliation.md`](https://github.com/daiedy/Test_CAP/tree/f50d60015972bc2fc020ea056195c4d00552dc6c/docs/features/pipeline-metrics/research/reconciliation.md) section 5): `claude-opus-5-5` input 4, cacheWrite5m 5, cacheWrite1h 8, cacheRead 0.20, output 20; `claude-sonnet-5` 2 / 2.5 / 4 / 0.20 / 10; `claude-sonnet-5-5` 2 / 2.50 / 4 / 0.20 / 10 (added in fix round 1, VERIFICATION F2: the model `docs-keeper`, `ui-verifier` and `upstream-watcher` resolve to; verified against the same page, fetched 2026-09-29); `claude-haiku-4-5-20251001` 1 / 1.25 / 2 / 0.10 / 5. An unknown model gives `costUSD: null` for that model and a warning `unknown-model:<name>`, never a silent zero. **Partial cost**: an aggregate (an agent row, a phase row, the rework sum, the total) whose parts include an unpriced model sums the priced parts and is marked partial (`costPartial: true`, `reworkPartial` for the rework sum); the card prints `≥$x`, or `n/a` when no part is priced; `reworkShare` is `null` when the cost or the rework cost is `null`; `reconcile` gives `transcriptUSD` and `recovered` as `null` when nothing is priced. **History line**: `record` refuses while an `unknown-model` warning is present, because a partial figure in the committed line would compare as a real drop in cost (the price table is completed first); `record --force` writes the line with `costPartial: true`, so `compare` can tell it apart.

## 3. Time

- D5 **Timeline** of a scope (a session, a feature, or one agent) = the sorted timestamps of its `assistant` and `user` records; subagent records are merged into the session's timeline. Gap `g_i = t_{i+1} - t_i`. A gap is a **tool gap** when record `i` is an `assistant` record whose last content block is `tool_use` with a name other than `AskUserQuestion` (its result arrives when the user answers) and other than `Agent`/`SendMessage` (the subagent's own records fill that time on the merged timeline); every other gap is a **turn gap** (Claude finished, the user or a background agent is next). A record is one point once: a record whose `uuid` was already read from another file of the scope (copied history, D1) is not a second point.
- D6 **Active time** = Σ `min(g_i, cap_i)` with `cap = IDLE_MS` (5 min) for a turn gap and `cap = TOOL_MS` (10 min, the Bash tool's maximum `timeout`; the Stop gate allows 700 s) for a tool gap. Both constants live once in `scripts/lib/pipeline-metrics.mjs`, are overridable by CLI flags (`--idle`, `--tool`) and are printed in the card header. Idle while the user is away drops out by construction; a background agent working while the user is away counts through its own records. `system/turn_duration` is not used (one turn stayed open 17.7 h with a background agent, `pendingBackgroundAgentCount: 1`). Measured on #7 in phase 2 step 3 under D5: main thread 152.1 active min of 5,098.1 wall min, the same with a single 5-minute cap and with the 5/10 caps; the prototype's 162.3 (of 5,103.6) put every timestamped record on the timeline, where 2 `system/away_summary` records add 7.9 min and the `queue-operation` records 2.2 min by splitting idle gaps, while `attachment`, `stop_hook_summary`, `turn_duration` and `local_command` add 0.
- D7 **Lead time** = `t_last - t_first` of the scope. **Waiting for the user** = lead − active (includes nights). Per feature, lead runs from the first record on the feature's branch (or its `/spec` prompt, see [`data-flow.md`](data-flow.md) join rule) to the last.
- D8 **Agent-minutes** = Σ over the main thread and every agent of the active time computed on that thread's own records (D6 on the unmerged timeline: an agent counts its own file's records after D1 and D5 drop the copied ones; an `agent-<id>` file copied into a second session is the same thread). **Parallelism** = agent-minutes / active time of the merged timeline; ≥ 1 by construction. Cross-check per session: `cost-state.totalAPIDuration + totalToolDuration` (#7: 171.7 + 27.8 min) is a lower bound of the merged active time.

## 4. Attribution

- D9 **Agent** = the transcript file: main thread, or `agent-<id>` with `agentType` from `.meta.json` (live: `agent_type` from the hook input; `<id>` equals the `agent_id` of the MCP audit). **Launch** = an `Agent` tool_use in the main thread (`input.subagent_type`); **resume** = a `SendMessage` tool_use whose `input.to` is an agent id (#7: 11 launches, 23 resumes over 8 agents); **relaunch** = a further launch of an `agentType` already launched in the feature.
- D10 **Feature** = every record whose `gitBranch` is `feature/<name>`, across all sessions of the project directory, plus the records of a session between a `prompt` marker `{ command: 'spec' | 'feature', arg }` naming the feature (by kebab name or `#N`, resolved through `docs/features/<name>/` or the issues cache `.pipeline/issues.json`) and the next command marker. Measured: sessions span features (`0bb70a42` holds #5 and #6) and features span sessions (#6 in `0bb70a42` and `0f92618d`; `catalog-authorization` in `e9ead85a` and `29ece8c2`), so the join is per record, never per session. History before the event log: branch only; a `/spec` run on `main` before this feature is unattributed (stated in the card as `spec: not attributed`).
- D11 **Phase** = the value of the `- Phase:` line of `docs/STATE.md` at the moment the `/feature` orchestrator edits it (PostToolUse `phase` marker, [`data-flow.md`](data-flow.md)): the first integer 0-7 in the value, else `none`. The number is the `/feature` skill's phase everywhere: 0 preparation, 1 plan, 2 backend, 3 UI, 4 verification, 5 review, 6 documentation, 7 completion; the STATE line and a plan's Steps table use the same numbers, and a feature without UI has no phase 3 (user decision 2026-09-29, VERIFICATION F6). A record at time `t` belongs to the latest marker before `t` of the same feature; before the first marker: phase `0`. **Round** of a phase = number of markers with that phase number (a phase re-entered after a defect counts again). Fallback without markers (history): the **home phase** of the agent type: `architect`, `ux-designer` → 1; `cap-backend-dev`, `test-backend` → 2; `fiori-app-dev`, `ui5-freestyle-dev`, `test-ui` → 3; `ui-verifier` → 4; `reviewer` → 5; `docs-keeper` → 6; main thread → `orchestration`.
- D12 **Rework**, judged per launch, first against the plan, then by home phases (plan-aware, user decision 2026-09-29, VERIFICATION F6). A launch is **planned** when the feature's plan assignment (below) lists its agent type for the phase of the launch; a planned launch is never rework. A launch that is not planned is judged by the home-phase rule: (live, with markers) rework when the D11 phase at launch differs from the agent type's home phase; (history, without markers) the phase at launch is unknown but at least `H`, the highest home phase launched before it in the feature, so the launch counts as planned when the plan lists its type in any phase ≥ `H`, and is otherwise rework when its home phase is lower than `H`. A launch before the first `phase` marker of its feature takes the home-phase fallback instead of D11's phase `0` and is never rework (user decision 2026-09-29). Agent types without a home phase are never rework. **Rework share** = cost of rework launches / feature cost.
- **Plan assignment** of a feature = the pairs (phase, agent type) of the `## Steps` table of its `PLAN.md`: the header row names the `Phase` and `Agent` columns; per row, phase = the first integer 0-7 of the `Phase` cell (D11's rule: `5a Review follow-up` gives 5), agent types = every backticked token of the `Agent` cell that is a `HOME_PHASE` key other than `main` (`orchestrator`, prose and file names are ignored); a row without both contributes nothing. **Where the PLAN is read from** (user decision 2026-09-30, PLAN open question 9): the plan **as approved at the plan gate**, not the final one. It is the text of `docs/features/<name>/PLAN.md` in the first commit of `git log --full-history --reverse --format=%H -- docs/features/<name>/PLAN.md` for which `planApproved(text)` holds, read with `git show <commit>:<path>`; `planApproved` is true when the first `Status:` value of the text begins with `approved`, optionally in backticks (`draft`, `proposed` and a later `` `done` `` status that mentions the approval do not qualify). The status line decides, never the commit message. One walk serves a feature in work and a pruned one: the path's history outlives the prune, and the deletion commit holds no file and is skipped. `--full-history` is required: git's default history simplification drops a path that was created and deleted on a merged feature branch, so without it #5, #6 and #7 list no commit. Before the approval is committed (a `/spec` run before its commit), the working tree counts when its own status passes `planApproved`. No approved version (never marked approved, or no git) counts as no readable PLAN in the fallback below; the first committed version is not used, because it can be a draft (`catalog-authorization`'s first commit `efb05bf` reads `Status: draft`). Measured 2026-09-30, the first approved commit per feature, every one with `Phase` and `Agent` columns, none on the fallback: `pipeline-metrics` `c10c4f0`, `catalog-authorization` `3fdd195` (after the drafts `efb05bf`, `c9d9839`), #5 `69eb82a`, #6 `5775578`, #7 `fdf5327`. A `feature` report uses its feature's plan; a `session` report uses the plan of the feature named by the session's latest `phase` marker, else none. **Fallback**: no readable PLAN, no `## Steps` section, no `Phase` or `Agent` header column, or no row with a pair (older plans, or a Phase column without numbers as in `templates/feature/PLAN.md` today) means no plan assignment: every launch is judged by the home-phase rule alone, the report carries `reworkSource: 'home-phase'` (else `'plan'`), and the card header prints `rework: home-phase fallback` next to D11's `phases: markers` or `phases: home-phase fallback`.

## 5. Reconciliation against `cost-state` (the 27% dollar gap)

`cost-state` is a cumulative snapshot per Claude Code process, not per session ([`research/reconciliation.md`](https://github.com/daiedy/Test_CAP/tree/f50d60015972bc2fc020ea056195c4d00552dc6c/docs/features/pipeline-metrics/research/reconciliation.md) 2.6): the records of one process share `startTime`, their totals only grow, and the last (largest) one is the process total; one process can write into several session files (`e9ead85a` and `29ece8c2` share `startTime` 1789008726629, last total $97.25) and one session can span several processes (`488be2d6`: $21.03 and $381.99), so summing per session gave $143.48 for a real $97.25. **Reference total** of a scope = Σ over the distinct `startTime`s found in its sessions of that process's last `totalCostUSD`. A process whose sessions also hold records outside the scope contributes its proportional share, the process total × the scope's transcript cost in those sessions ÷ the transcript cost of those sessions whole (both after D1), the share the parser already applies per session. Records carry `timestamp: null` and `hasUnknownModelCost` (false in #7); an open session may hold none (`0f92618d`). Per model a record holds `inputTokens`, `outputTokens`, `thinkingTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens` (not split 5m/1h), `costUSD`. Transcript sums (D1) of `6ecbd7a4`, whose only process appears in no other session, against it:

- H4 Cache write rate: the prototype priced all writes at the 1h rate; the measured 5m/1h split changes the dollar figure without changing the token gap.
