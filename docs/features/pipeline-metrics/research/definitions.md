# pipeline-metrics: definitions and measured transcript facts

Date: 2026-09-29. Author: `architect`. Read by `cap-backend-dev` (steps 2-4), `test-backend` (step 5), `reviewer`. Every figure below was measured on session `6ecbd7a4` (feature #7, `products-excel-upload`) with narrow `jq` filters; no conversation content was read. Claude Code version in the records: 2.1.282.

## 1. Sources and their status

| Source | Path | Status | What it gives |
|---|---|---|---|
| Main transcript | `~/.claude/projects/<slug>/<session>.jsonl`; `slug` = cwd with `/` replaced by `-`; hook input `transcript_path` | internal, unstable; read only through `scripts/lib/transcript-usage.mjs` | usage, timestamps, tool calls, `gitBranch`, `cost-state` |
| Subagent transcript | `<session>/subagents/agent-<id>.jsonl` + `agent-<id>.meta.json`; hook input `agent_transcript_path` | internal | the agent's usage and timeline; meta: `agentType`, `description`, `requestShape` (`background`), `toolUseId`, `spawnDepth` |
| Hooks | `SessionStart`, `UserPromptSubmit`, `SubagentStart`, `SubagentStop`, `Stop`, `PreCompact`, `PostToolUse` | official API | markers (phase, prompt, gate) and the official transcript paths |
| MCP audit | `.pipeline/mcp-audit-<session>.jsonl` (ADR-0014) | project API | MCP-first compliance, `skipped-unjustified`, `ok:false` |
| Event log (new) | `.pipeline/metrics-<session>.jsonl` | project API, shapes in `research/data-flow.md` | everything the hooks can see |
| Baseline (new) | `docs/metrics/history.jsonl` | committed | one line per finished feature |

Record fields the parser reads, nothing else (`slim()` in `scripts/lib/transcript-usage.mjs` for transcript records, `sessionFiles()` for the meta file); each is an opaque identifier, a number or a type check, never content:

- Opaque identifiers: `type`, `uuid`, `requestId`, `agentId`, `gitBranch`, `version` (the Claude Code version, printed in the card header, PLAN Risks), `subtype` of a `system` record, `message.model`; in the `message.content[]` blocks of an `assistant` record: `type`, `name` of a `tool_use` (the tool name; the last block's type and name classify the gap, D5), `id` of an `Agent` tool_use (joins a launch to its agent file through the meta `toolUseId`), `input.subagent_type` of `Agent`, `input.to` of `SendMessage` when it is a string (an agent id); in `agent-<id>.meta.json`: `agentType`, `toolUseId` (`description` is not read); on `cost-state`: `startTime` (the process key, section 5) and the model keys of `modelUsage`.
- Numbers (a time, token counts, durations, dollars, line counts): `timestamp`; `message.usage.{input_tokens, cache_creation_input_tokens, cache_creation.ephemeral_5m_input_tokens, cache_creation.ephemeral_1h_input_tokens, cache_read_input_tokens, output_tokens, output_tokens_details.thinking_tokens}`; on `cost-state`: `totalCostUSD`, `totalAPIDuration`, `totalToolDuration`, `totalDuration`, `totalLinesAdded`, `totalLinesRemoved`, and per model `inputTokens`, `outputTokens`, `thinkingTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens`, `costUSD`.
- Type and presence checks, kept as a boolean: `toolUseResult` of a `user` record (present or not); the type of `message.content` of a `user` record (a string is a user prompt, an array holds tool results; the value is not kept); `hookErrors` of a `stop_hook_summary` record (non-empty means a blocked Stop, the gate history fallback; the entries are not read); `hasUnknownModelCost` on `cost-state`.

Text, thinking, prompt content, tool inputs other than the two keys above, tool results and hook error texts are never kept: `slim()` reduces each line right after `JSON.parse`. `message.stop_reason` is not read; D1 takes the maximum over snapshot records without it.

Record types seen in the main file (1,193 lines): `assistant` 287, `user` 179, `system` 107 (`turn_duration` 49, `stop_hook_summary` 55, `away_summary` 2, `local_command` 1), `cost-state` 1, `attachment` 237, `file-history-snapshot` 10, plus UI state (`ai-title`, `atis-latch`, `last-prompt`, `mode`, `queue-operation`). Subagent files hold only `assistant`, `user`, `attachment`.

## 2. Request and tokens

- D1 **Request** = the set of `assistant` records sharing one `requestId` across the whole scope, in every file that holds them; the scope is a session with its subagent files, or the session set of a feature (#7 main: 287 records, 162 requests; every record has a `requestId`). Usage of a request = per field the **maximum** across all its records in every file; a request id seen in several files counts once. Measured: in the main file all records of a request carry identical usage; in subagent files the usage grows with the stream (opus output summed over first records 126,403, over last records 226,811), and 78% of #7's subagent requests exist only as snapshots with `stop_reason: null`, whose output and thinking stay provisional (`research/reconciliation.md` H3). Summing every record overcounts (main cache read 52.2M instead of 29.9M). A resumed or forked session copies earlier history into its own file with the same `requestId` and `uuid` (`29ece8c2` repeats 118 of its 119 main-thread requests of `e9ead85a`, and all 66 subagent requests of `e9ead85a` under the same `agent-<id>` file name; all 119 user records of `29ece8c2`'s main file carry a `uuid` of `e9ead85a`, 118 with the same `timestamp`), so counting per file double-counted 25% of `catalog-authorization` ($87.50 instead of $65.39). A copied request belongs to the thread of the first file that holds it in a fixed order (session id, main file before subagent files, then file name); a copy always sits in the same kind of thread (main to main, `agent-<id>` to the same id).
- D2 **Tokens by kind** per request: `input` (uncached), `cacheWrite5m` and `cacheWrite1h` (`cache_creation.ephemeral_*`; their sum equals `cache_creation_input_tokens`), `cacheRead`, `output` (includes thinking; `output_tokens_details.thinking_tokens` is reported as a detail, not priced separately), `model` from `message.model`. `<synthetic>` records (2 in #7, zero usage) are skipped and counted under `skipped`. Measured 5m/1h split in #7: opus 3.52M / 0.65M, sonnet 1.21M / 0 (the prototype priced every write at the 1h rate).
- D3 **Context of a call** = `input + cacheRead + cacheWrite5m + cacheWrite1h`; per agent: average and peak. **Cache hit ratio** = Σ cacheRead / Σ context. Measured #7 (prototype figures): about 130K per call, 95% of token volume is cache read.
- D4 **Cost** = Σ over models and kinds of `tokens × price[model][kind] / 1e6`, prices from `scripts/lib/model-pricing.json` (`recordedAt`, `perMTok`). Seed values, verified against https://platform.claude.com/docs/en/about-claude/pricing (fetched 2026-09-29) and matching `model-pricing.json` (`research/reconciliation.md` section 5): `claude-opus-5-5` input 4, cacheWrite5m 5, cacheWrite1h 8, cacheRead 0.20, output 20; `claude-sonnet-5` 2 / 2.5 / 4 / 0.20 / 10; `claude-haiku-4-5-20251001` 1 / 1.25 / 2 / 0.10 / 5. An unknown model gives `costUSD: null` for that model and a warning `unknown-model:<name>`, never a silent zero.

## 3. Time

- D5 **Timeline** of a scope (a session, a feature, or one agent) = the sorted timestamps of its `assistant` and `user` records; subagent records are merged into the session's timeline. Gap `g_i = t_{i+1} - t_i`. A gap is a **tool gap** when record `i` is an `assistant` record whose last content block is `tool_use` with a name other than `AskUserQuestion` (its result arrives when the user answers) and other than `Agent`/`SendMessage` (the subagent's own records fill that time on the merged timeline); every other gap is a **turn gap** (Claude finished, the user or a background agent is next). A record is one point once: a record whose `uuid` was already read from another file of the scope (copied history, D1) is not a second point.
- D6 **Active time** = Σ `min(g_i, cap_i)` with `cap = IDLE_MS` (5 min) for a turn gap and `cap = TOOL_MS` (10 min, the Bash tool's maximum `timeout`; the Stop gate allows 700 s) for a tool gap. Both constants live once in `scripts/lib/pipeline-metrics.mjs`, are overridable by CLI flags (`--idle`, `--tool`) and are printed in the card header. Idle while the user is away drops out by construction; a background agent working while the user is away counts through its own records. `system/turn_duration` is not used (one turn stayed open 17.7 h with a background agent, `pendingBackgroundAgentCount: 1`). Measured on #7 in phase 2 step 3 under D5: main thread 152.1 active min of 5,098.1 wall min, the same with a single 5-minute cap and with the 5/10 caps; the prototype's 162.3 (of 5,103.6) put every timestamped record on the timeline, where 2 `system/away_summary` records add 7.9 min and the `queue-operation` records 2.2 min by splitting idle gaps, while `attachment`, `stop_hook_summary`, `turn_duration` and `local_command` add 0.
- D7 **Lead time** = `t_last - t_first` of the scope. **Waiting for the user** = lead − active (includes nights). Per feature, lead runs from the first record on the feature's branch (or its `/spec` prompt, see `data-flow.md` join rule) to the last.
- D8 **Agent-minutes** = Σ over the main thread and every agent of the active time computed on that thread's own records (D6 on the unmerged timeline: an agent counts its own file's records after D1 and D5 drop the copied ones; an `agent-<id>` file copied into a second session is the same thread). **Parallelism** = agent-minutes / active time of the merged timeline; ≥ 1 by construction. Cross-check per session: `cost-state.totalAPIDuration + totalToolDuration` (#7: 171.7 + 27.8 min) is a lower bound of the merged active time.

## 4. Attribution

- D9 **Agent** = the transcript file: main thread, or `agent-<id>` with `agentType` from `.meta.json` (live: `agent_type` from the hook input; `<id>` equals the `agent_id` of the MCP audit). **Launch** = an `Agent` tool_use in the main thread (`input.subagent_type`); **resume** = a `SendMessage` tool_use whose `input.to` is an agent id (#7: 11 launches, 23 resumes over 8 agents); **relaunch** = a further launch of an `agentType` already launched in the feature.
- D10 **Feature** = every record whose `gitBranch` is `feature/<name>`, across all sessions of the project directory, plus the records of a session between a `prompt` marker `{ command: 'spec' | 'feature', arg }` naming the feature (by kebab name or `#N`, resolved through `docs/features/<name>/` or the issues cache `.pipeline/issues.json`) and the next command marker. Measured: sessions span features (`0bb70a42` holds #5 and #6) and features span sessions (#6 in `0bb70a42` and `0f92618d`; `catalog-authorization` in `e9ead85a` and `29ece8c2`), so the join is per record, never per session. History before the event log: branch only; a `/spec` run on `main` before this feature is unattributed (stated in the card as `spec: not attributed`).
- D11 **Phase** = the value of the `- Phase:` line of `docs/STATE.md` at the moment the `/feature` orchestrator edits it (PostToolUse `phase` marker, `research/data-flow.md`): the first integer 0-7 in the value, else `none`. A record at time `t` belongs to the latest marker before `t` of the same feature; before the first marker: phase `0`. **Round** of a phase = number of markers with that phase number (a phase re-entered after a defect counts again). Fallback without markers (history): the **home phase** of the agent type: `architect`, `ux-designer` → 1; `cap-backend-dev`, `test-backend` → 2; `fiori-app-dev`, `ui5-freestyle-dev`, `test-ui` → 3; `ui-verifier` → 4; `reviewer` → 5; `docs-keeper` → 6; main thread → `orchestration`.
- D12 **Rework** (live) = a launch while the current phase marker differs from the agent type's home phase; (history) = a launch whose home phase is lower than the highest home phase launched so far in the feature. A launch before the first `phase` marker of its feature takes the home-phase fallback instead of D11's phase `0`: its phase is the agent type's home phase and the live rule does not flag it as rework (user decision 2026-09-29). **Rework share** = cost of rework launches / feature cost. #7 by the history rule: architect (after fiori-app-dev), ux-designer, architect (after reviewer), ui-verifier (after docs-keeper): 4 of 11 launches, ≈19% of cost (prototype pricing; 22% with every cache write at the 1h rate).

## 5. Reconciliation against `cost-state` (the 27% dollar gap)

`cost-state` is a cumulative snapshot per Claude Code process, not per session (`research/reconciliation.md` 2.6): the records of one process share `startTime`, their totals only grow, and the last (largest) one is the process total; one process can write into several session files (`e9ead85a` and `29ece8c2` share `startTime` 1789008726629, last total $97.25) and one session can span several processes (`488be2d6`: $21.03 and $381.99), so summing per session gave $143.48 for a real $97.25. **Reference total** of a scope = Σ over the distinct `startTime`s found in its sessions of that process's last `totalCostUSD`. A process whose sessions also hold records outside the scope contributes its proportional share, the process total × the scope's transcript cost in those sessions ÷ the transcript cost of those sessions whole (both after D1), the share the parser already applies per session. Records carry `timestamp: null` and `hasUnknownModelCost` (false in #7); an open session may hold none (`0f92618d`). Per model a record holds `inputTokens`, `outputTokens`, `thinkingTokens`, `cacheReadInputTokens`, `cacheCreationInputTokens` (not split 5m/1h), `costUSD`. Transcript sums (D1) of `6ecbd7a4`, whose only process appears in no other session, against it:

| Model | input | cache write | cache read | output | note |
|---|---|---|---|---|---|
| opus-5-5 | 1,522 vs 289,089 (1%) | 4.17M vs 4.67M (89%) | 100.4M vs 133.3M (75%) | 226,811 vs 653,814 (35%) | `thinkingTokens` 226,569 equals the transcript output within 0.1% |
| sonnet-5 | 702 vs 117,186 (1%) | 1.21M vs 1.36M (88%) | 58.0M vs 69.9M (83%) | 82,047 vs 176,961 (46%) | `thinkingTokens` 68,136 |
| haiku-4-5 | absent vs 903 | | | 15 | no `assistant` record uses haiku: an auxiliary call (title generation) |

Dollar view: $62.88 recovered of $85.73, 73% with the verified 5m/1h prices (88%, $75.25, when every cache write is priced at 1h, as the prototype did). Candidates step 3 tests, in this order, each with the kind and model it would explain:

- H1 Auxiliary API calls without an `assistant` record: main-thread records carry `advisorModel` and `serverClassifierRequest` fields; `ai-title` records exist; haiku appears only in `cost-state`. Would explain uncached `input` (1% recovered), part of cache read and output for both models.
- H2 Aborted or retried requests (`totalAPIDuration - totalAPIDurationWithoutRetries` = 175 s in #7) stream usage that Claude Code counts but never lands as a record.
- H3 Output semantics: Claude Code's `outputTokens` may add the running snapshot of every streamed chunk, or count thinking twice; the equality `thinkingTokens ≈ Σ max output` is the lead. Test: sum `output_tokens_details.thinking_tokens` (13,264 on first records) against both fields.
- H4 Cache write rate: the prototype priced all writes at the 1h rate; the measured 5m/1h split changes the dollar figure without changing the token gap.
- H5 Compaction summaries and the `<synthetic>` model: none and 2 records with zero usage in #7; expected to explain nothing.

Rule for v1 (ADR-0022; warning basis decided by the user on 2026-09-29 after step 4): the parser reports per model and kind `transcript`, `costState`, `ratio`. When `cost-state` exists, the card shows the recovered ratio and `unattributed = reference total − Σ agents` as its own row, as information without a threshold, so the total equals Claude Code's own figure: in auto mode with subagents the ratio is structurally 62-97% (snapshots without final output, H3, 41% of #7's gap; calls outside the transcript, H1, 59%), and only the non-auto control `ecb6d00e` reaches 100%. The card and `reconcile` warn, never fail, when the **pricing self-check** of a model diverges by more than `PRICING_TOLERANCE = 0.05`: the last record of each process in scope, its `inputTokens`, `cacheCreationInputTokens` (split 5m/1h by the transcript's share for that model), `cacheReadInputTokens` and `outputTokens` priced with `model-pricing.json`, against its `costUSD`; #7 is exact for sonnet and within 0.2% for opus, so a divergence signals a stale price table. The per-agent and per-phase split stays proportional to what the transcript attributes.
