The deviation is technically forced and acceptable: in cds 10.0.6 `prepareError` (`node_modules/@sap/cds/lib/req/response.js:21-27`) turns `req.error(400, 'KEY', args)` into `{ code: 400, message: 'KEY', args }`, and `normalized()` (`lib/srv/protocols/http.js:123-131`) replaces `code` by the key only when `e.code == e.status`; that holds for the top-level error of `req.reject` (status inferred as 400) but not for a collected detail (no `status`), so every `details[].code` would stay `400` and the tests that assert the `PRODUCTS_IMPORT_*` codes could not pass. Same API, no second mechanism. → `docs-keeper` (phase 6): extend the PATTERNS row "Business logic error" with "several collected messages: `req.error({ status, code: 'KEY', args })` per message; the positional form leaves the status in `details[].code`", align CONVENTIONS line 69, add a LESSONS entry; `architect`: a one-line note under ADR-0021 decision 4 that the implementation uses the object form; user: `.claude/rules/srv-handlers.md` "Errors" (protected file).
