# docs-toolchain: context

Date: 2026-10-14. Author: `architect`. Branch: `feature/docs-toolchain` (spec written on `spec/products-validations`, issue #27).

This file is the brief for the implementers: every agent of the feature reads it whole (protocol step 1), so it holds only the sections below (ADR-0018). No screens: the feature changes no Fiori page (Swagger UI is a development page of a third-party package), so there is no `SCREENS.md` and no `ux-designer` step. Experiments, measurements, rejected mechanisms and framework facts are in `research/docs-facts.md`, read only by `architect` and `reviewer` unless a plan step names the file.

## Request
Make the documentation that already exists in the sources reach its consumers, in three parts (issue #27, items 1, 2 and 4 of the chat proposal of 2026-10-14; item 3, the business-rules wiki, is #28 and is blocked by this feature). First, the 16 CDS doc comments and the descriptions still to be written must arrive in CSN (registry), in `$metadata` (`Core.Description`) and in an OpenAPI export, which needs the compiler switch `cdsc.docs` and a decision on where a description is written, because a doc comment on a `db/` entity does not propagate to its service projection. Second, a command `npm run docs:api` that exports the service to a committed OpenAPI document under `docs/`, plus a live Swagger UI in development (`cds-swagger-ui-express`). Third, `eslint-plugin-jsdoc` in the existing lint path for `srv/**` and `app/**/webapp/ext/**`, so that the CONVENTIONS section 4 requirement "JSDoc on every exported function" is checked by a gate instead of by eye, and a generated JSDoc page for `srv/` and `ext/`. The user's wider wish behind the issue (recorded in the orchestrator's memory): human-readable documentation of the business logic, the CDS model and the API, for people and for the agents.

## User decisions
Plan gate, 2026-10-14: the user accepted the architect's recommendation on every question ("all by the recommendations"); ADR-0029 accepted the same day.
1. Descriptions are CDS doc comments only, never `@description` or `@Core.Description` in project CDS; placement per artefact kind as in ADR-0029 decision 2: `db/` entity as a developer note, projection and its own elements in `srv/annotations/<Entity>.cds`, service, action, type and singleton at their definition.
1b. Descriptions are English literals, the recorded exception to invariant 7 (ADR-0029 decision 3); no i18n keys for descriptions.
2. OpenAPI document `docs/api/CatalogService.openapi3.json`, JSON, English, written by `npm run docs:api` and by `npm run docs:registry`, stamped `info.x-sources`, checked by `scripts/check-docs-fresh.mjs` and byte-compared in `test/api-docs.test.js`; `@protocol: 'odata-v4'` on the service (decision 4).
3. JSDoc page from the in-house extractor in `scripts/gen-registry.mjs` into `docs/registry/JSDOC.md` (decision 5); no jsdoc-to-markdown, no TypeDoc.
4. The jsdoc rule set of decision 7 blocks (`require-jsdoc` on exported functions and handler class methods in `srv/`, on every function in `ext/`; `require-param`, `require-param-description`, `require-returns`, `require-returns-description`, `check-param-names`), the rest warns; the `ext/` gate is option A: `checkUi5` in `scripts/lib/file-checks.mjs` runs the app ESLint (PLAN step 4), plus `lint:js` in CI and `/test-all`.
5. `@title: 'Product Catalog API'` and `@Core.SchemaVersion: '1.0.0'` on the service (decision 3).

Fixed by the issue: the scope is items 1, 2 and 4 above; protected pipeline files (`scripts/lib/**`, `.claude/rules/**`, `.claude/skills/**`, `package-lock.json`) are touched, so the implementation session is started with `PIPELINE_ALLOW_PROTECTED=1` and the protected edits sit in their own phase (PLAN step 4); the draft question of the architect workflow does not apply (no data editing changes in the Fiori app).

### Interface for #28 (business-rules wiki)
- OpenAPI: `docs/api/CatalogService.openapi3.json`, OpenAPI 3.0.2 JSON, English only, regenerated by `npm run docs:registry` (or `npm run docs:api`), fresh when `info['x-sources']` equals the registry header hash. Useful fields: `info.title`/`description`/`version`, `tags[].name` and `tags[].description` (one per entity set, description = the projection's doc comment), `components.schemas['CatalogService.<Entity>'].title` (the projection's doc comment, converter quirk) and `.properties.<element>.description` (the element's doc comment), `paths['/Products/CatalogService.importProducts'].post.summary` (the action's doc comment).
- JSDoc: `docs/registry/JSDOC.md`, markdown rendered on github.com without a build, one `##` per source file (repo-relative path), one `###` per documented symbol with its signature, description, parameters and return value; same freshness header as the registry files.
- Descriptions in CSN: `definitions[name].doc` and `elements[name].doc` for every project projection and element (`cds.load('*')` with `cds.cdsc.docs`), also readable through `mcp__cds-mcp__search_model`; `docs/registry/DOMAIN-MODEL.md` shows them per entity and element.

## Applicable patterns
- "OData contract" and "metadata.xml snapshot update" (PATTERNS Tests, Infrastructure): the `cdsc.docs` switch and every doc comment change `$metadata`; snapshot and `metadata.xml` are regenerated in PLAN step 2.
- "Dependency update" (PATTERNS Infrastructure): two new dev dependencies at the root and one in `app/products` need an ADR and a user-started `PIPELINE_ALLOW_PROTECTED=1` session; `package.json` and `package-lock.json` change only through `npm install`. ADR-0029 is that ADR.
- "Shared function for several handlers" (JSDoc on `srv/lib` exports) and CONVENTIONS section 4: the requirement the new lint rule enforces.
- "Record a wish" / "Finish a feature" (ADR-0019): #27 is closed with `SUMMARY.md`; #28 is unblocked.
- ADR needed (no PATTERNS row): where a description is written and in which form (doc comment or annotation, which file, which language); a generated API document and its freshness; a JSDoc page generator; the JSDoc rule set and its gates. All four are decisions 1-8 of the draft `docs/decisions/ADR-0029-docs-toolchain.md`.

## Relevant lessons
- 2026-10-09 (LESSONS): in a worktree session the Bash guard refuses compound commands (`&&`, variables, `*` with `npx`); implementers run plain single commands or a scratch `.mjs` with `node <file>`, as this spec's probes did.
- 2026-10-12 (LESSONS): `cds-mcp` `search_model` shows the pre-feature model in a worktree session; here it already shows `doc` fields, because the MCP server compiles with docs on regardless of the project switch; do not take that as proof that the switch is set.
- 2026-10-12 (LESSONS): long agent runs hit their turn limits; the generator and the hook work of steps 3 and 4 are written incrementally with the tests, the last completed item named when stopping.
- CHANGELOG 2026-09-11 (architect rule): a measured contract figure names the phase it describes; here one contract phase (step 2) with two figures, 1604 for the switch alone and about 1670 for the full description set.
