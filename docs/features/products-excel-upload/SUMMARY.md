## What was done

- **Model/service**: new collection-bound action `importProducts(in: many $self, file: ProductsImportFile not null) returns Integer` in the `Products` projection (`srv/catalog-service.cds`), new type `ProductsImportFile` (`content: LargeBinary @Core.MediaType`, `mediaType @Core.IsMediaType`, `fileName @Core.ContentDisposition.Filename`, `@Core.AcceptableMediaTypes` xlsx only); `@mandatory` on the parameter `file` (`srv/annotations/Products.cds`). First `srv/lib` module, `srv/lib/products-import.js` (header mapping, cell coercion, row reading, `unzippedSize`/`MAX_UNZIPPED_BYTES`), and the handler `on('importProducts', Products)` in `srv/catalog-service.js`: one `INSERT` per row inside the transaction so `@mandatory`/`@assert.*` fire per row and attribute their error to a row number, all-or-nothing (`PRODUCTS_IMPORT_NOTHING_IMPORTED` first, then every row message, no cap), duplicate names against the file and the catalog, at most 1,000 rows. `@cds.server.body_parser.limit: '1mb'` on `CatalogService` (research 5.6: a realistic 1,000-row file is 221-558 KB, 413 at the CAP default 100 KB). New runtime dependency `read-excel-file` 9.3.10 and devDependency `write-excel-file` 4.1.1 (`package.json`/`package-lock.json` via `npm install` in a `PIPELINE_ALLOW_PROTECTED=1` session, decision 10). 9 `PRODUCTS_IMPORT_*` message keys in `_i18n/messages.properties`/`messages_ru.properties`; the success text is localized by hand with `cds.i18n.messages.at(key, req.locale, args)` (cds 10.0.6 does not localize `sap-messages`); several collected messages use the object form `req.error({ status, code, args })` (the positional form leaves the numeric status in `details[].code` once more than one message is collected, cds 10.0.6).

## Deviations from the plan

- **Focus after a failed empty submit** (`REVIEW.md` Minor 1). SCREENS/research 6.5 predicted focus moves to the file field; `VERIFICATION.md` scenario 4 measured `document.activeElement` staying on `<body>` instead, while `ui-verifier`'s scenario 9 (a fresh `Enter`-driven dialog open, not an error-recovery re-focus) placed focus on the field correctly. `reviewer` traced this to UI5 1.152.0's own `ActionRuntime-dbg.js` `validateProperties` path (no project code involved) and judged it not blocking: the value state, error text and "no request sent" parts of the same scenario all passed, and the `valueStateText` sits in a polite live region regardless of DOM focus. `SCREENS.md` "Required marker" and "Empty submit" now read "Focus on the field (6.5 measured; not reproduced by `ui-verifier`)" instead of asserting the move as fact.
- **The framework's own validation reason inside `PRODUCTS_IMPORT_ROW_INVALID` stays English in a `ru` session** (e.g. `Value abc is not a valid Decimal(10,2)`), exactly the risk `SCREENS.md` "UX risks" flagged in advance and asked to record. Not a defect: the project's own wrapper text ("Row {0}, column ...") is `ru`; only cds's own `ASSERT_*`-family bundle entry (`{2}`) is not, because cds 10.0.6 does not ship a ru translation for every framework assertion message (`DRAFT_ALREADY_EXISTS` has the same gap, `docs/LESSONS.md` "Pending upstream", pre-existing).
- **Stale test-count figures found by `reviewer`**, corrected in this phase: the phase 3 `CHANGELOG.md` line said "31 `opaTest`s"; the tree has 40 (36 pre-existing + 3 in `ImportProductsJourney.js` + 1 in `RussianLocaleJourney.js`) plus 2 QUnit = 42 in the runner, matching `reviewer`'s own re-run.
- **A one-off `RatingRangeFilterJourney` "Rating 2 to 4 shows 9 products" timeout** on the first `test:ui` gate run of phase 3 (unrelated journey, unrelated feature #6); the rerun was green and `reviewer` confirmed `ImportProductsJourney` cannot affect it (registered after it in `opaTests.qunit.js`, no data change, Cancel only) and that it fits the known `liveMode` double-request behaviour already in `docs/LESSONS.md`. Not treated as open debt: a single, explained, non-reproduced occurrence.
- All PLAN acceptance criteria are met; the two behavioral deviations above are recorded, not defects that reopen a criterion.

## Lessons

7 entries added to `docs/LESSONS.md` in this phase (full text there): "Pending" — FE V4 refreshes a List Report only after Create/Delete/draft actions/an action returning a different instance, so a scalar-returning action needs `Common.SideEffects` (now also in `PATTERNS.md`); a FE V4 action parameter is required only through `Common.FieldControl` from `@mandatory`, not `Nullable="false"`, and the asterisk lands on the `Label` (now also in `PATTERNS.md`); a request body-size limit does not bound what an uploaded archive unzips to, and a `worker_threads` `resourceLimits.maxOldGenerationSizeMb` does not help because inflated entries are external `Buffer` memory outside the V8 heap it governs; `write-excel-file` 4.1.1 writes zip entries with a data descriptor (size discovered by scanning), not a declared size, so fixtures built with it exercise a different guard path than a workbook with sizes in its headers; per-`it` `afterEach` cleanup (not only end-of-`describe`) keeps a red assertion from leaving rows that shift later counts. "Pending upstream" — cds 10.0.6's positional `req.error(status, key, args)` leaves the numeric status in `details[].code` once more than one message is collected in a response (workaround: the object form, now in `PATTERNS.md`/`CONVENTIONS.md`); cds 10.0.6's `sap-messages` header never localizes a key into the caller's `Accept-Language` (workaround: `cds.i18n.messages.at`, now in `PATTERNS.md`). A tooling note (not upstream, not cds/UI5-specific) also went in: the `Write`/`Edit` tools decode a literal `\u` escape into the real character before writing to disk, so Russian test data meant to hold a literal escape must be checked with a grep for non-ASCII after writing.
