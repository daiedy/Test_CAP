## 2. Framework facts (verified by MCP, 2026-10-09)

- capire "Input Validation > `@assert.target`" (`mcp__cds-mcp__search_docs`): the check applies to a managed to-one association, validates user input on `CREATE` and `UPDATE`, "is performed on the application service layer before the custom application handlers are called", answers 400 with `target` = the foreign key (`author_ID` in the example), and expects the target entity in the same service ("Cross-service checks are not supported"). `CatalogService.Products.currency` targets `CatalogService.Currencies` (autoexposed projection on `sap.common.Currencies`, `mcp__cds-mcp__search_model`), the same shape as `category` to `CatalogService.Categories`. The HANA warning ("views with joins or unions can't be locked") does not apply: `Currencies` is a plain projection on a table, and HANA is not configured (STATE open debt).
- The internal `INSERT` of `importProducts` (`srv.run(INSERT.into(Products).entries(entry))`, `srv/catalog-service.js` line 52) runs the same input validation: proven on `main` by `test/catalog-service.test.js` "importProducts rejects the whole file and reports every bad row", whose fixture row 5 (`Import Unknown Category`, category `NOPE`) is reported as `Row 5, column "category": ...` through `ASSERT_TARGET` on `category`. `columnOf('currency_code')` already maps back to the workbook column `currency` (`IMPORT_COLUMNS` in `srv/lib/products-import.js`), so a currency failure is reported as `Row N, column "currency": <framework reason>` with no handler change.
- Currencies data: `db/schema.cds` line 2 `using from '@sap/cds-common-content'`; the installed package 3.2.0 ships `db/data/sap-common-Currencies.csv` (204 data rows, quoted `code,name,descr,minorUnit`, `USD` line 181, `EUR` line 59, `GBP` line 64; no `XXX`, no `XTS`). `sap.common.Currencies` is `@cds.persistence.skip: 'if-unused'` and is used by `Products.currency`, so the in-memory table exists and the CSV loads; `test/catalog-service.test.js` "exposes Currencies as a code list for the value help" reads `USD` from the running service on every `npm test`. The annotation therefore rejects only unknown codes, not everything.
- Test fixtures: `test/fixtures/products-import-valid.xlsx` uses `USD`, `EUR`, `GBP`; `products-import-invalid.xlsx` uses `USD` in every row (read with `read-excel-file/node` on the scratch copy). No existing import test changes its message list when `currency` gains `@assert.target`. `db/data/my.catalog-Products.csv` has `USD` in all 15 rows and prices from 14.99 to 1299.99, which fit `Decimal(15, 2)` unchanged: no CSV edit, no "migration" in development.
- capire "Serving Fiori UIs > Role-based Visibility" (`mcp__cds-mcp__search_docs`): the main example writes `$Path: '/CatalogService.EntityContainer/Configuration/isAdmin'` and the details block "SAP Fiori elements also allows to not include it in the path" shows `$Path: '/Configuration/isAdmin'`. Both are documented; ADR-0013 part 8 already names the short form as the fallback. `mcp__fiori-mcp__search_docs` ("Hiding UI Elements with the UI.Hidden Annotation") has no page on the singleton path form; it states that a `UI.Hidden` `Path` "must reference a Boolean property" and that `edmJSON` expressions are OData V4 only. The `catalog-authorization` review (CHANGELOG 2026-09-16) root-caused the TypeError as "a container-qualified `$edmJson` `$Path` is valid FE-converted metadata but not a valid OData V4 data-binding path"; `/Permissions/isEditor` is a valid absolute OData V4 binding path to the singleton property, which is why the short form is expected to remove the error. Expected, not measured: a browser measurement is PLAN step 8.
- Decimal mapping (capire "OData > Type Mapping"): `cds.Decimal(p, s)` maps to `Edm.Decimal` with `Precision`/`Scale`; no client-side conversion happens for a precision change. `@cap-js/sqlite` returns Decimal values as strings (TESTING.md "cds 10 specifics"); SQLite stores them with REAL affinity, so a value with 15 significant digits (the widened range's edge, 9999999999999.99) sits at the limit of double precision. Only relevant if Q1 widens the range: the test then uses a value that round-trips (for example `1234567890123.45`) and asserts the string.
