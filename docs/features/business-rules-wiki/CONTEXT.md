## Request
Issue #28: a wiki of small, human-readable pages that holds every business decision and business rule of the Product Catalog together with its change history, readable by any person without the AI. The source of truth is the folder `docs/wiki/` in the repository with the same hierarchy as the wiki, mirrored one-way to the GitHub Wiki of this repository. On top of the pages a generated link graph and lookup commands let the agents load only the pages they need for a task instead of the whole documentation, without slowing the model down. The user's own wording (2026-10-14, paraphrased): one new Markdown file is not enough to hold many business rules; a whole wiki of small files holds everything about the business decisions with their changes recorded; a graph-based lookup lets the AI load the needed pages on demand without polluting its context; everything is human-readable and well structured, short but meaningful; it lives in the GitHub built-in wiki with a duplicate folder in the project of the same hierarchy. Structure proposed in the chat: `Home`, a per-folder index, `domain/` (one page per entity in plain language), `rules/` (one page per rule: stable id, one-sentence statement, why, where it fires and what the user sees, status, since, history table), `how-to/` (user scenarios), `decisions/` (plain-language digest of each ADR), `api/` (generated from OpenAPI), a glossary; every page with a one-sentence summary, tags and the code paths it describes in the frontmatter. Blocked by #27 (done 2026-10-26, ADR-0029): the wiki consumes `docs/api/CatalogService.openapi3.json`, the doc comments and `docs/registry/JSDOC.md`.

## What already exists and is reused
From `docs/registry/REUSE-CATALOG.md`, `HANDLERS.md`, `UI-ARTIFACTS.md`, `JSDOC.md` and the scripts:
- Generated-file stamping and freshness (ADR-0017, ADR-0029): the first-line header read by `recordedHash()` of `scripts/lib/registry-sources.mjs` is reused for the generated Markdown of the wiki (header without a date, so `npm run docs:wiki` is idempotent); the `x-sources` stamp and the `apiDocsStatus()` shape of `scripts/gen-api-docs.mjs` are the model for `graph.json` and `wikiStatus()`; `check-docs-fresh.mjs` gets one more reasons source and keeps its `--fix` through `gen-registry.mjs`, which already chains `writeOpenApi` and will chain `writeWiki`. No second freshness mechanism.
- Shape checks (ADR-0018): `sections()` and the `offending()` idiom of `scripts/lib/doc-shapes.mjs` are extended with `wikiPageShapeErrors`; `checkDocShapes` of `file-checks.mjs` already dispatches by path; `test/doc-shapes.test.js` is the test home; `scripts/check-feature-docs.mjs` shows how a top-level script imports from `scripts/lib/`.
- Glob matching: `isUnder()` of `scripts/lib/hook-utils.mjs` (brace alternatives since ADR-0029 D) resolves the `code` globs of a page in `for-path` and in the hash of `verified`; `createHash('sha256')` sliced to 16 hex as in `sourcesHash()`.
- Test precedents: `test/api-docs.test.js` (byte comparison of a generated file with a fresh run in a temp folder, `check-docs-fresh.mjs` spawned in a temp project, the `REGISTRY_FILES` list), `test/doc-shapes.test.js` (template accepted, mutations rejected), `test/backlog.test.js` (a CLI spawned with `process.execPath`), `test/fixtures/hook-sandbox.mjs` `createSandbox()` for the `file-checks` test.
- CI and Dependabot: `ci.yml` pins actions by commit with a version comment and installs with `npm ci --ignore-scripts`; the `github-actions` ecosystem of `dependabot.yml` already bumps pinned actions weekly, so the new action pin needs no Dependabot change; `dependabot-automerge.yml` is the precedent for `permissions: contents: write`.
- Sources of the pages (links, never copies): `docs/registry/DOMAIN-MODEL.md` (element tables and descriptions), `SERVICES.md` (projections, restrictions, actions), `HANDLERS.md`, `JSDOC.md`, `docs/api/CatalogService.openapi3.json` (the API page is generated from it), `docs/decisions/ADR-*.md` (a digest links its ADR and paraphrases the Decision paragraph only), `docs/features/*/SUMMARY.md` (History rows link the path, which survives the prune), `docs/architecture/PATTERNS.md` (a rule page names the pattern row by title), `README.md` (the workbook columns of the import how-to).
- What would be a mistake to write anew: a second hash or header format (use `recordedHash`, the `sources:` header, `x-sources`); a second glob matcher (use `isUnder`); a Cyrillic scan with its own scope (the wiki scan in `wikiStatus` uses the hook's character range, U+0400 to U+04FF, on `docs/wiki/**/*.md`; the hook keeps its scope); a copy of the ADR text, of a registry table, of the OpenAPI document or of a PATTERNS row inside a page; a Markdown link resolver that understands `[[wikilinks]]`; a per-agent "wiki index" in agent memory (the CLI is the index); a second place for message texts (pages quote the key and link `_i18n/messages.properties`).
- Nothing suitable exists for: a frontmatter parser (none in `scripts/`; a small YAML-subset reader for scalars and flat lists is written in `gen-wiki.mjs`, no dependency), a link graph, the lookup CLI, the mirror workflow. They are the first of their kind, built on the pieces above.

## Applicable patterns
Rows from `docs/architecture/PATTERNS.md`:
- "Generated API documentation" (ADR-0029): `npm run docs:registry` writes generated documents stamped with the sources hash, `check-docs-fresh.mjs` and a test guard them, never edited by hand; the wiki's generated files follow it one for one (`docs:wiki` next to `docs:api`).
- "Advisory from a Stop hook" (ADR-0023): names the only way to add a non-blocking Stop message; this plan deliberately adds none (the stale audit runs in CI, `/test-all` and the phase 6 gate), the row is the reference if a Stop advisory is wanted later.
- "Finish a feature" (ADR-0019): the prune keeps `SUMMARY.md`, which is why a History row links `docs/features/<name>/SUMMARY.md` and the ADR, never a file the prune removes.
- "Record a wish, order the queue" (ADR-0019): the issue is the request; nothing is written to the issue by this spec except the plan link at approval.
- "Dependency update": no new dependency, so the row's ADR and `npm install` path are not needed; `gen-wiki.mjs` and `wiki.mjs` use Node built-ins and the installed `@sap/cds` (for `audit`).
- "Pipeline metric" (ADR-0022): unchanged; the feature's cost is recorded in `SUMMARY.md` "Cost" as usual.
- No row exists for a documentation wiki, a link graph, a lookup before an edit, a page staleness audit or a GitHub Wiki mirror: ADR needed: `docs/decisions/ADR-0030-business-rules-wiki.md`, decisions 1-8, accepted by the user on 2026-10-26.

## Relevant lessons
From `docs/LESSONS.md`:
- 2026-10-26 (docs-toolchain, CI): a suite that needs a second install names it in the CI job; the new `audit` and `test/wiki.test.js` need only the root install, stated in the plan; the feature branch is pushed and opened as a pull request so CI runs before the merge.
- 2026-10-26 (docs-toolchain, tooling): a matcher gets one test per promised syntax, and "no report" is not "an empty report": the frontmatter reader and the link resolver get one test per accepted form (scalar, flat list, missing key; same-folder, cross-folder, repository, external and anchor links), and `wikiStatus` distinguishes "no generated file" from "stale".
- 2026-10-26 (docs-toolchain, generated documents): the served document is not the exported one; here the mirrored wiki is not the folder when `export` runs, so the verification compares a mirrored page with its source page.
- 2026-10-26 (reviewer on a large branch): write the file first and grow it; the backfill is split into six `docs-keeper` launches by folder, each writing pages from the first turn.
- 2026-10-12 (long agent runs): name the last completed item when stopping; the orchestrator resumes `docs-keeper` with SendMessage per folder.
- 2026-10-09 (worktree sessions): the Bash guard refuses compound commands; the lookup commands are single `node scripts/wiki.mjs ...` calls on purpose.
- 2026-10-09 (`cds add data` touches `mta.yaml`): no data generation here; the risk list still asks the implementer to read `git status` for unexpected files after `npm run docs:registry`.
