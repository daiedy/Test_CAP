## What was done

- Model: `my.catalog.Categories : sap.common.CodeList` with the key `code : String(20)`, `UPPER_SNAKE` codes (ADR-0010); `Products.category` moved from `String(50)` to `Association to Categories`, the foreign key `category_code : String(20)` is generated by the compiler. Data: 6 categories with a `ru` translation, 15 products with real `category_code` values.
- Service: explicit `@readonly` projection `Categories`, `@assert.target` on `Products.category`, titles and i18n keys for `Categories`. The OData contract changed deliberately: `category` (Edm.String) → `category_code` (Edm.String 20) + the `category` navigation.
- UI: `app/products/annotations/Products.cds`: `Common.Text`, `Common.TextArrangement: #TextOnly`, `Common.ValueListWithFixedValues: true` on the `category` association; the manual `@Common.ValueList` removed, the ValueList is now generated by the compiler from `sap.common.CodeList` (ADR-0011). New `app/products/annotations/Categories.cds` with `Common.Text: name` on the `code` key, without which the list items would show the code. Mock data and `metadata.xml` synchronized.
- Backend tests: `test/catalog-service.test.js` extended from 7 to 13 tests (category list, localization with fallback to `en`, filter and `$expand` by `category_code`, `@mandatory`/`@assert.target`, `@readonly`), `test/metadata.test.js` without code changes, the snapshot updated twice (after the backend and after the UI annotations): 15 tests, all green.
- UI tests: Test Starter scaffold (`testsuite.qunit.html/js`, `Test.qunit.html`), page objects `pages/*.gen.js` from `@sap-ux/ui5-test-writer`, custom page object `pages/CategoryDropdown.js` for the typeahead table of the fixed value help; four OPA5 journeys (`FilterProductsByCategoryJourney`, `CategoryShownAsNameJourney`, `RussianLocaleJourney`, `EditCategoryOnObjectPageJourney`); run with `npm run test:ui` in `app/products` against `npm run watch` in the root.
- Manual verification (`ui-verifier`, `VERIFICATION.md`, 5 screenshots): List Report (column, multi-select dropdown filter, token combination, network `$filter` inside `$batch`), Object Page (name in the header and in General Information, no Edit), the `ru` locale, keyboard scenario, accessibility tree, browser console free of feature errors.
- Documentation: ADR-0010, ADR-0011 accepted; `PATTERNS.md` (5 rows), `templates/annotations-ui.cds`, `STACK.md`, `TESTING.md`, `CHANGELOG.md`, `STATE.md`, `LESSONS.md` updated; the registry regenerated.

## Reused

- The pattern "Code list with selection from a list" (`Currency` from `@sap/cds/common`) as the starting point for `Categories`.
- The `localized`/`sap.common.TextsAspect` mechanism: `Categories.texts` translations without a single handler.
- `mcp__cds-mcp__search_model` on `Products`, `Currencies`, `CodeList`, `CatalogService` in the research phase; `search_model` on `CatalogService.Currencies` in the design phase found a ready example of `Common.Text` on a CodeList key.
- The existing mock mode scaffold (`sap-fe-mockserver`, `ui5-mock.yaml`): only the Categories data was added, the mechanism did not change.

## Deviations from the plan

- Step 12 (`webapp/i18n` texts) skipped by decision of `ux-designer`: no new UI keys were needed, all text comes from `Common.Text`/`@title` via the `srv` i18n.
- The UI tests are not run the way the rule template originally assumed (`npx ui5-test-runner --url http://localhost:8080/...` with `npm start`): the working combination is `npm run test:ui` in `app/products` against `npm run watch` (:4004) in the root, because `fiori run` (:8080) does not serve `/products/webapp` from the FLP sandbox.
- The test pages (`testsuite.qunit.html`, `Test.qunit.html`) bootstrap from the same CDN as the application (`https://ui5.sap.com/resources/...`), not from `../resources/` through the proxy; otherwise the test frame and the application frame would end up on different `sap.fe` versions.
- The `EditCategoryOnObjectPageJourney` journey is implemented but marked `opaTest.skip`: `Products` has no draft, the Object Page does not show the "Edit" button, the scenario of editing the category in the form is physically not verifiable in this feature (a risk foreseen in PLAN, not a new defect).

## Pipeline defects found (fixed during the feature)

- The `metadata.xml` snapshot / contract snapshot command must build the whole model (`cds compile '*' ... -s CatalogService -l en`), not only `srv`: otherwise the UI annotations from `app/` do not get into the snapshot (`4bfecd8`).
- `npm run watch` (`cds-serve --watch`) failed in cds 10 (`this.load is not a function`); replaced with `cds watch` (`ce05c8a`). `npm start` deliberately kept on `cds-serve` per the CAP documentation.
- `fiori run` (`npm start`, :8080) does not bring up the application through the FLP intent from `flpSandbox.html` (does not serve `/products/webapp`, the UI5 versions of the proxy and of the CDN bootstrap diverge): the only working entry point is :4004; closed together with the `modernize-flp-sandbox` debt.
