With cds 10.0.6 defaults (`fiori.lean_draft: true`, `bypass_draft: true`, `draft_new_action: false`, lock 15 min, deletion 30 d) a draft-enabled entity behaves like this for plain HTTP clients and `cds.test`: `POST /Products {...}` without `IsActiveEntity` creates a **draft** (201, `IsActiveEntity: false`) and skips `@mandatory`/`@assert.target`; `POST` with `IsActiveEntity: true` creates an active record and runs every assertion; `PATCH`/`DELETE`/`GET` by `(ID)` alone address the active record; `GET ...?$count` counts active only; `draftActivate` enforces `@mandatory`, `@assert.range`, `@assert.target` with 400 (targets `in/name`, `in/stock` for drafts of active records, bare `category_code` for new drafts); `@assert.*` on a draft PATCH are `DraftMessages` with 200; any write to the active while a draft exists (own or foreign) answers 409 `DRAFT_ALREADY_EXISTS`; `DELETE /Products(<id>)` of a draft-only record answers 403 `DRAFT_ACTIVE_DELETE_FORBIDDEN_DRAFT_EXISTS`. `CDS_FIORI_DRAFT_NEW_ACTION=true` as an environment variable did not add `draftNew` to `$metadata` (compile-time option; would need `package.json`). EDMX diff of `@odata.draft.enabled` on `CatalogService.Products`: 131 added lines, nothing removed; `Categories` (`@readonly`) and the generated value list untouched; no `DraftAdministrativeData` entity set (`ContainsTarget`). `@sap/cds/_i18n` ships `Draft_*` labels incl. `ru`. `@sap-ux/fe-mockserver-core` 1.7.15 defaults `IsActiveEntity/HasActiveEntity/HasDraftEntity` for mock records and emulates `draftEdit`/`draftActivate`.

**Why:** Planning `products-draft-edit` (2026-09-07). The documentation snippets about "bypass drafts by default" read as if a plain POST created an active record; the runtime shows it creates a draft unless `IsActiveEntity: true` is sent. Without the experiment three existing negative tests would have gone red in phase 2. Full log: `docs/features/products-draft-edit/CONTEXT.md`, "Verified by experiment".

**How to apply:** For any future draft-enabled entity (or a second FE app that edits data) do not re-run the experiment; plan tests with explicit `IsActiveEntity: true` payloads and `(ID=...,IsActiveEntity=true)` keys, discard drafts with `IsActiveEntity=false`, match activation error `target` by suffix. If the user picks `draft_new_action` or `direct_crud` instead (ADR-0012 alternatives), that path is unverified and needs a fresh scratchpad run with `package.json` configuration. Check whether ADR-0012 was accepted and whether `docs-keeper` updated PATTERNS "Drafts", TESTING "cds 10 specifics" and `templates/service.test.js` (the template still had the stale `category: 'Furniture'` on 2026-09-07).
