# ADR-0022: Pipeline metrics from hooks and the transcript, one committed line per feature

Date: 2026-09-29. Status: accepted (user, 2026-09-29, feature `pipeline-metrics`).

## Context
The pipeline has no measure of its own cost. The user asked (#14) how long each agent and each `/feature` phase works, how many tokens and dollars each costs, with idle time excluded, and which further figures agentic pipelines are usually judged by. Today the only figures are Claude Code's session total (`/cost`), the MCP audit counts read by `/retro` (ADR-0014), and the prompt-size ratchet (ADR-0018). A prototype of 2026-09-29 (issue #14, session `6ecbd7a4`, feature #7) showed that every `assistant` record of the Claude Code transcript carries `message.usage`, `message.model`, `requestId`, `timestamp` and `gitBranch`, that subagent transcripts sit next to the main one with a `.meta.json` naming the `agentType`, and that a `cost-state` record holds Claude Code's own total; the prototype recovered 88% of it. The transcript format is documented as internal and unstable; hooks are the sanctioned API and already carry `agent_id`, `agent_type`, `agent_transcript_path` and `transcript_path`. `docs/STATE.md`'s `Phase:` line is already rewritten by the `/feature` orchestrator after every gate. PATTERNS has no row for a pipeline metric or for reading transcripts (CLAUDE.md invariant 4). Definitions and measurements: `docs/features/pipeline-metrics/research/definitions.md`; record shapes and outputs: `research/data-flow.md`.

## Decision
Five parts. (1) **Definitions**: a request is the set of `assistant` records sharing a `requestId`, its usage the per-field maximum; tokens are counted by kind (input, cache write 5m and 1h, cache read, output) per model and priced from one dated table `scripts/lib/model-pricing.json`; active time is the sum of gaps on the merged timeline of main and subagent records, a turn gap capped at 5 min and a tool gap (after a `tool_use` other than `AskUserQuestion`, `Agent`, `SendMessage`) at 10 min; lead time is first to last record, waiting is lead minus active, agent-minutes add per thread; a feature is every record on `feature/<name>` plus the span after a `/spec` or `/feature` prompt naming it; a phase is the integer of the `Phase:` line of `docs/STATE.md` at the orchestrator's edit, with the agent type's home phase as the fallback for history; a launch outside its home phase is rework. (2) **Sources**: hooks write markers and aggregates; the transcript is read only by `scripts/lib/transcript-usage.mjs` through the official `transcript_path` and `agent_transcript_path` (directory walk only for history), tested on a synthetic fixture that holds only structural keys, and self-checked against `cost-state` with a warning below 95% recovered and an `unattributed` row so the card's total equals Claude Code's. (3) **Event log**: `.pipeline/metrics-<session>.jsonl`, records `session`, `prompt` (command token and argument only), `agent-start`, `agent-stop` (aggregate), `phase`, `gate` (reason), `compact`, `turn-end`, pruned after 30 days; a shared `metrics-log.mjs` with the shape and lifecycle of `mcp-audit.mjs`. (4) **Committed output**: `docs/metrics/history.jsonl`, one line per finished feature written by `scripts/metrics.mjs record` in phase 6, and a `## Cost` section in the feature `SUMMARY.md` holding the card; raw data never leaves `.pipeline/`. `/feature` phase 7 prints the card, `/retro` reads gate blocks and rework, the SessionStart briefing prints the last history line. (5) **Non-goals**: OpenTelemetry export (later, as an independent cross-check without attribution), dashboards or pages, per-user figures.

## Alternatives
| Option | Why rejected |
|---|---|
| Claude Code OpenTelemetry (`claude_code.token.usage`, `cost.usage`, `active_time.total`) as the source | no per-agent or per-phase attribution; needs a collector; kept as a later cross-check |
| Hooks only, no transcript | hooks carry no usage or timestamps of API calls; per-agent tokens and active time are impossible without the transcript |
| Transcript only, no hooks | no phase markers, no gate reasons, no official paths; every figure would depend on an internal directory layout |
| `system/turn_duration` as active time | a turn stayed open 17.7 h while a background agent ran; it measures the turn, not the work |
| A single 5-minute cap for every gap | a legitimate `npm test` or `test:ui` run of 6-10 minutes is cut to 5; the tool gap is recognisable by the record before it |
| Feature attribution by session | sessions span features (#5 and #6 in one) and features span sessions (#6, `catalog-authorization` in two); the record-level `gitBranch` is exact |
| A new instruction to every agent to log its time | duplicates what the transcript already records and depends on compliance |
| Commit the raw event log or transcripts | conversation content and volume in git; the aggregate line and the card are enough to compare features |
| Price table inline in the code | a price change would be a code change without a date; the table is dated and sourced, and `cost-state` flags drift |
| A field-stripped real transcript as the fixture | risk of leaking content and of pinning one Claude Code version's quirks; a synthetic fixture with hand-computed expectations is exact |

## Consequences
- New: `scripts/lib/transcript-usage.mjs`, `scripts/lib/pipeline-metrics.mjs`, `scripts/lib/metrics-log.mjs`, `scripts/lib/model-pricing.json`, `scripts/metrics.mjs`, `scripts/hooks/user-prompt.mjs`, `scripts/hooks/subagent-start.mjs`, `docs/metrics/history.jsonl`, `test/metrics.test.js`, `test/hooks-metrics.test.js`, `test/fixtures/transcript-fixture.mjs`, `test/fixtures/metrics-log.jsonl`.
- Changed: seven hooks append one record kind each; `.claude/settings.json` registers `UserPromptSubmit` and `SubagentStart`; the `feature` and `retro` skills, the `docs-keeper` prompt, `templates/feature/SUMMARY.md` (`## Cost`), `CLAUDE.md` documentation map, `scripts/i18n/pipeline*.properties`; `test/prompt-budget.json` re-recorded (ADR-0018).
- PATTERNS gains an Infrastructure row "Pipeline metric": a new figure is a formula in `pipeline-metrics.mjs` fed from the event log or the parser, with a fixture case; never a second reader of transcripts or of `.pipeline/`.
- The `/feature` orchestrator writes `Phase: <N>: <label>` so the marker is unambiguous; every finished feature carries a card, and the next feature is compared against it with `metrics.mjs compare`.
- Harder: a Claude Code update can change the transcript; the version is printed, the self-checks warn, and the fixture is the place to encode a new shape. Every implementation session for this area runs with `PIPELINE_ALLOW_PROTECTED=1` (rule `pipeline-config.md`).
