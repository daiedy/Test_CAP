With cds 10.0.6 mocked auth (`lib/srv/middlewares/auth/basic-auth.js`): requests without an `Authorization` header pass as anonymous until `@requires`/`@restrict` demands a user, then 401 + `WWW-Authenticate: Basic realm="Users"` (also for `$metadata` and the service root). `cds.requires.auth.users` in `package.json` deep-merges with the eight default users and `"*": true` (roles arrays replaced per user; `tenant` dropped when not multitenant). Users without `password` accept any password; unknown names are authenticated without roles (403 on restricted entities, 200 on unrestricted ones). `@restrict: [{grant:'READ',to:'Viewer'},{grant:'*',to:'Editor'}]` on a draft-enabled projection: Viewer gets plain 403 `'403'` on POST (active and NEW draft), PATCH, DELETE, `draftEdit`; 404 on a foreign draft; 403 `DRAFT_LOCKED_BY_ANOTHER_USER` on PATCH/activate/discard of a foreign draft; two Editors keep the 409 `DRAFT_ALREADY_EXISTS` lock. `@requires`/`@restrict` change nothing in the EDMX (0 diff lines) and CAP derives no `Capabilities` from them. `cds.test`: `{ auth: null }` per request sends no header (error `status: 401`, numeric `code: 401`); denied role gives `code: '403'` (string); a test file without `defaults.auth` (`test/metadata.test.js` at the time) fails with 401. `cds compile srv --to xsuaa` yields scopes/role templates `Viewer`, `Editor`. `ui5-test-runner` 5.14.0: `--basic-auth-username/--basic-auth-password` are browser-script options (after `--`), best supplied via `app/products/ui5-test-runner.json` `{ "browserArgs": [...] }` so CI's `npm run test:ui -- --report-dir ...` keeps working. `mcp__fiori-mcp__search_docs` was down that day ("embeddings service failed to initialize").

**Why:** Planning `catalog-authorization` (2026-09-07). The documentation does not say whether entity grants cover the lean-draft actions, whether the mock user block replaces the defaults, or that a `$metadata` HTTP test without auth breaks; the template `templates/service.test.js` "denies anonymous access" used a named user (`nobody`) that is in fact authenticated by `*`. Full log: `docs/features/catalog-authorization/CONTEXT.md`, "Verified by experiment".

**How to apply:** Do not re-run the experiment for the same model. For any new restricted entity: plan `defaults.auth` in every test file, anonymous tests with `auth: null`, role tests with `carol` (default `admin`, unknown to the model) or `viewer`; keep `bob` an Editor while the draft lock test exists. If the user picks another role model in ADR-0013 (single role, `"*": false`, prefixed names) only the mock users and the negative tests change; the runtime behavior above still holds. Check whether ADR-0013 was accepted and whether `docs-keeper` fixed CONVENTIONS section 2 ("restrict" listed under `srv/annotations/`), TESTING rule 5 and `templates/service.test.js`; flag as debt if not. See also [[cds10-draft-behavior]].
