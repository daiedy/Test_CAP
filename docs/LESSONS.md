Status: Pending products-details-section; no rule change needed.
- 2026-10-12. UI5 V4 `refreshDependentListBindingsWithoutCache` refreshes a dependent list binding without its own cache on every `requestSideEffects` of the parent, even a `DraftMessages` read, which rebuilt the Details rows (focus lost R2-D2, list validation message lost R2-D5, tokens recreated R2-D6). Fix: give edit-state list bindings `$$ownRequest: true` (own `GET` per load) and build read-only list items from expanded data instead of binding them. Status: Pending products-details-section; transfer to the PATTERNS "Custom section or column" row (done in this change), then remove.
- 2026-10-12. A custom fragment that writes data needs its mechanisms decided at plan time: the plan promised "the selection sync" and the browser proof refuted three mechanisms (a two-way key writes while typing, a section-bound child binding cannot `create()`, rows missing after `draftEdit`). Fix: decide a one-way key with a commit write, a validation control message, own-request child bindings and a re-read after `draftEdit` in the plan, and prove each in a skeleton first (step 7 did). Status: Pending products-details-section; transfer to the `architect` prompt.
- 2026-10-12. A criterion that names a verb must be measured for every verb: the first ADR said a top-level child `DELETE` was refused like `POST` and `PATCH`; the phase 2 measurement showed it is authorized like a `DELETE` through the root (R22). Fix: one test per verb the criterion names (here the top-level `DELETE` test). Status: Pending products-details-section; transfer to the `architect` and `test-backend` prompts.
- 2026-10-12. Verification measured a defect that was only a stale browser module cache (R2-D4): chrome-devtools MCP `navigate_page` `ignoreCache` does not bypass the HTTP cache for UI5 module loads. Fix: verify a fix in a NEW isolated browser context and prove the fresh code with a DOM difference (TESTING "cds 10 specifics"). Status: Pending products-details-section; transfer to the `ui-verifier` prompt.
- 2026-10-12. `cds-mcp` `search_model` returns the pre-feature model in a worktree session, so a new entity of the feature is invisible to it. Fix: for a feature's own entities read `docs/registry/DOMAIN-MODEL.md` (regenerated) or the CDS files, and say so in the report. Status: Pending products-details-section; no rule change needed.
- 2026-10-12. Long agent runs hit their turn limits during phases 3, 4 and 5 of #9. Fix: write the document or file incrementally from the first finding (protocol step 10), name the last completed item when stopping, and resume the same agent with `SendMessage`. Status: Pending products-details-section; already in the protocol, the cost is the budget per phase.

Plan the writers in the same phase (import column plus fixtures plus `README.md`, `newProduct` in the tests). Status: Pending products-subcategory-cascade; transfer to the PATTERNS "Mandatory field" row ("list every writer of the field in the plan") or the `architect` prompt.

When the plan gate changes behaviour, `architect` step 1b reconciles SCREENS in the same step. Status: Pending products-subcategory-cascade; transfer to the `architect` prompt (protected file).
