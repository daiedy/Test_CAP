## Request
GitHub issue #20 (P1, no blockers): close three model and contract debts of `docs/STATE.md` in one feature. (1) Change `Products.price` from `Decimal(10, 2)` to the conventional `Decimal(15, 2)` and amend ADR-0003, which keeps the old precision as a "historical exception". (2) Give `Products.currency` an `@assert.target` so that an unknown code such as `XXX` is rejected on create and on the Excel import `importProducts`, after checking that `sap.common.Currencies` has data (otherwise the annotation would reject everything). (3) Move the `UI.*Hidden` annotations of `app/products/annotations/Products.cds` from the container-qualified `$Path` `/CatalogService.EntityContainer/Permissions/isEditor` to the short `/Permissions/isEditor` and verify in a browser that the UI5 `$select` TypeError logged when the Object Page opens disappears while Create, Delete and Edit stay hidden for `viewer`. The issue expects one snapshot update, one `metadata.xml` regeneration and one verification.

## User decisions
Approved on 2026-10-09 by the user (/spec #20, "approve" without amendments, so the four recommendations of PLAN "Open questions" stand): 1) `@assert.range` of `price` stays `[0, 99999999.99]`; 2) ADR-0003 is amended in place with an `## Amendment` section, `Status:` untouched, no ADR-0024; 3) if the short path does not remove the TypeError or breaks the hidden state, step 8b reverts to the container-qualified path and the STATE row closes as "upstream, no local fix"; 4) two contract regenerations, one per phase, each with its own figure.

## What already exists and is reused
- `@assert.target` on `Products.category` (`srv/annotations/Products.cds` line 12) is the precedent for the annotation and for every test idiom: "rejects an unknown category code (@assert.target)" (active `POST`, `ASSERT_TARGET`, `target: 'category_code'`) and "reports an unknown category on the draft and rejects activation (@assert.target)" (`DraftMessages`, `rejectedWith(/400/)`, target suffix regex) in `test/catalog-service.test.js`; the new currency tests copy these with `currency_code: 'XXX'`.
- The import validation path exists end to end: `importProducts` inserts one row at a time through the service (`srv/catalog-service.js` `importProducts`, `validationErrors`), the framework's `ASSERT_*` details are mapped to `PRODUCTS_IMPORT_ROW_INVALID` with the workbook column (`columnOf` in `srv/lib/products-import.js` already maps `currency_code` to `currency`), and the invalid fixture proves it for `category` (`Row 5, column "category"`). No handler, message key, i18n text or library change is needed for the currency; writing a currency check in the handler would duplicate the framework's validation (ADR-0021 decision 3, PATTERNS "Bulk create from a file").
- Workbook helpers for the new import test: `workbook(data)`, `fileParameter(bytes)`, `HEADER` in `test/fixtures/build-workbooks.mjs`, plus `importSheet`, `rejected`, `count` inside `describe('CatalogService.Products importProducts')`; no new fixture file. The existing fixtures use `USD`, `EUR`, `GBP` only, so no existing import test changes its expected messages.
- The ISO currency list and its texts ship with `@sap/cds-common-content` (`db/schema.cds` line 2) and load into the in-memory database on every start; nothing to seed.
- The contract tests and the regeneration recipe: `test/metadata.test.js` (whitespace-normalised `compact` comparison, `annotations(path)` helper), `templates/metadata.test.js`, PATTERNS "OData contract" and "metadata.xml snapshot update".
- `RoleAwareActionsJourney.js` (2 `opaTest`s, editor sees Create, Delete, Edit) and `ImportProductsJourney.js` guard the editor side of the four hidden consumers; the viewer side is the blocking `ui-verifier` criterion (TESTING.md "Known gaps", user decision 2026-09-10: no second runner config unless the hidden state regresses).
- `app/products/webapp/localService/mockdata/Permissions.json` (array form) serves `/Permissions` to the mock server; the short path needs no new fixture.
- Nothing to create in `srv/lib`, `ext/`, `_i18n` or `webapp/i18n`: `REUSE-CATALOG.md`, `HANDLERS.md` and `UI-ARTIFACTS.md` were checked; the feature adds no function, handler, fragment, formatter or text.

## Applicable patterns
- "Monetary amount": `Decimal(15, 2)` + `currency : Currency` + `@Measures.ISOCurrency: currency_code`; the example cell "`Products.price` (historical `Decimal(10, 2)`)" loses its parenthesis (ADR-0003 rule, amended in PLAN step 2).
- "Association target existence check": `@assert.target` in `srv/annotations/<Entity>.cds`, example `Products.category`; `Products.currency` becomes the second example.
- "Format or range check": `@assert.range` on `price` stays declarative; the bound is Q1.
- "Role-aware UI visibility" (ADR-0013 part 8): the singleton, the handler and the `$edmJson` `$Not` `$Path` stay; the path takes the documented short form `/Permissions/<flag>`, which ADR-0013 names as the fallback and capire shows in "Role-based Visibility" ("SAP Fiori elements also allows to not include it in the path"). The row's path text is updated by `docs-keeper` once the browser measurement confirms it (PLAN step 10).
- "Service test" and "OData contract": `test/catalog-service.test.js`, `test/metadata.test.js`; `npx vitest -u` and the `metadata.xml` regeneration in the phase of each model change (phase 2 and phase 3, figures in PLAN).
- "User scenario": no new OPA5 journey; `npm run test:ui` runs as the regression gate of phase 3.
- No new pattern and no new ADR: the three changes apply existing decisions. ADR-0003 and ADR-0013 get amendment sections in the shape of ADR-0021's amendments (PLAN "Decisions that require an ADR").

## Relevant lessons
- LESSONS 2026-09-16 (Pending upstream sapui5): the container-qualified `$Path` trips an unguarded `_Helper.aggregateExpandSelect` TypeError once when the Object Page opens, both roles, unchanged on UI5 1.153.0; the short path is the unproven local fix this feature measures.
- CHANGELOG 2026-09-16 (`catalog-authorization` review): the root cause is that the container-qualified path is valid FE metadata but not a valid OData V4 data-binding path; a visibility mechanism must be verified on the List Report and the Object Page separately, because an unresolved `$Not` binding defaulted differently per page.
- LESSONS 2026-10-07 (`ui-verifier`): Basic Auth priming for a second role needs a same-origin page first (`/favicon.ico`), then the prime.
- TESTING.md "cds 10 specifics": `POST` without `IsActiveEntity: true` creates a draft and skips `@assert.*`; on the draft a violated rule is a `DraftMessages` entry with 200 and a 400 only on `draftActivate`; `ASSERT_TARGET` targets are matched by a suffix regex; Decimal values arrive as strings.
- TESTING.md: OPA5 and `ui-verifier` run against `npx cds serve --in-memory --port 4004`, never `cds watch`; a leftover draft changes row counts.
- `architect` memory `test-suite-shape`: test counts are re-derived per plan (139 today, re-counted 2026-10-09), and quoted per phase gate.
- `products-rating-filter` VERIFICATION (git history, commit `63abadb`): the console baseline for `ui-verifier`; the `Permissions/isEditor` TypeError was listed there as known noise, which this feature turns into a "must be absent" criterion.
