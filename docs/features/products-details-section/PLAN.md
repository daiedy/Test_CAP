## Decisions for the user

Approved by the user on 2026-10-11 (plan gate): D1 = (i); D2, D3, D4, D5 and D9 as recommended; D6 confirmed ("Kharakteristiki" for the facet label and `TypeNamePlural`, "Kharakteristika" for `TypeName` and the Attribute column); D7 with the `ux-designer`'s refinements (`BATTERY_LIFE` = "Vremya avtonomnoy raboty", `CAPACITY` = "Obyem" with U+0435, `PRODUCTS_SUBCATEGORY_HAS_FOREIGN_DETAILS` `ru` with "ne sootvetstvuyut", units Latin and not localized, the inch unit `in`); D8 ADR-0026 accepted. SCREENS "Open questions for the user" 1-7 are answered the same way. The "Recommended default" column is the decision.

| # | Question | Recommended default | Alternatives and their cost |
|---|---|---|---|
| D1 | A product has detail rows and its subcategory changes | (i) Reject at Save, nothing deleted: the root constraint branch writes "Some detail rows do not fit the new subcategory" on the Subcategory field as soon as the draft subcategory changes (measured), Save lists each row that does not fit, the user deletes or changes them; cost 1 `when` branch, 1 message key, 0 handler, 2 tests | (ii) Delete the foreign rows silently on the draft PATCH, like `resetStaleSubcategory` resets the subcategory: a handler extension (`SELECT` the allowed attributes, `DELETE` from `ProductDetails.drafts`), the root branch stays for the active API path, +3 tests, a Fiori guideline breach (typed values vanish without confirmation). (iii) Keep rows and block only new foreign ones: not expressible declaratively, leaves inconsistent data; rejected |
| D2 | One row per attribute per product (user decision 6) | The duplicate `when` branch in the row's `@assert` (`PRODUCTS_DETAIL_ATTRIBUTE_DUPLICATE`, 400 with the rows named on active writes and at Save, a draft message on the row) and **no** `@assert.unique` on `ProductDetails`: measured, cds 10.1.1 with `@cap-js/sqlite` turns a `UNIQUE` violation into a 500 `ERR_SQLITE_ERROR` on the active path and writes nothing on a draft | `@assert.unique` as written: a 500 for a user error, no draft message; both together: the 500 wins on active writes |
| D3 | Key of `SubcategoryAttributes` | `cuid` plus `@assert.unique.pair: [ subcategory, attribute ]` in `db/schema.cds`: CONVENTIONS keep composite keys for text and code tables, nothing references the assignment row, the value help maps `attribute_code`, the CSV is the only writer and a duplicate pair fails at deploy | Composite key `(subcategory, attribute)`: saves the `ID` column and the one-line constraint, but makes the OData key a pair and deviates from CONVENTIONS section 3 for no consumer |
| D4 | Which elements of a detail row are mandatory | `attribute` and `value` both `@mandatory`: an inline row left empty blocks Save with `ASSERT_MANDATORY` on both cells (measured), so no empty rows are saved | `value` optional: rows with an attribute and no value are saved and shown empty |
| D5 | Adding a detail row before the product has a subcategory | Allowed; the dropdown is unfiltered while `product/subcategory_code` is null (the In parameter is empty), the row is checked at Save; the ADR-0025 flow (category, then mandatory subcategory) makes this rare | Hide the table's Create until a subcategory exists through `Capabilities.InsertRestrictions.NonInsertableNavigationProperties` with an `If` on `subcategory_code`: a new annotation shape, unmeasured, a follow-up issue if wanted |
| D6 | Section label and position | `en` "Details", `ru` "Kharakteristiki" (U+0425 U+0430 U+0440 U+0430 U+043A U+0442 U+0435 U+0440 U+0438 U+0441 U+0442 U+0438 U+043A U+0438, the usual catalogue word); the section sits after "Pricing & Stock" and before "Administrative Data"; `ux-designer` may move it in `SCREENS.md` | `ru` "Detali" (U+0414 U+0435 U+0442 U+0430 U+043B U+0438), the issue's literal word |
| D7 | Seed data | The three tables below: 20 attributes, 45 assignments (three per subcategory), 15 detail rows on 7 products; every product with rows keeps at least one assigned attribute free (the OPA5 journey adds "Battery Life" to Wireless Mouse) and 8 products show the empty state | Edit the lists at the gate; the figures do not change unless the attribute count changes the generated value lists (they do not) |
| D8 | ADR-0026 | Accept: EAV composition, reusable attributes via the assignment entity, value text plus unit, navigation-path In parameter, declarative set-membership constraints, no `@assert.unique` on the child, D1 as decided | Reject a decision: the plan returns to `architect` |
| D9 | Drafts | `@odata.draft.enabled` stays on `CatalogService.Products` only (ADR-0012); the rows are edited inside the product draft, every write to them goes through the root (lean draft answers 422 `DRAFT_MODIFICATION_ONLY_VIA_ROOT` otherwise, measured) | none that keeps Fiori Elements editing |

## Acceptance criteria
- [ ] The seeded details of Laptop Pro 15 are served through `Products(...)/details?$expand=attribute` with the attribute name and unit (Screen Size 15 in, Memory (RAM) 16 GB, Storage 512 GB), verified by test `test/catalog-service.test.js` "returns the seeded details of a product with attribute names and units"
- [ ] Attribute names are localized with English fallback (`RAM` in `ru` is the D7 value), verified by test "returns localized attribute names with English fallback"
- [ ] `SubcategoryAttributes?$filter=subcategory_code eq 'LAPTOPS'` returns exactly the three assigned attributes with `attributeName`, in `ru` on request, verified by test "lists the attributes assigned to a subcategory as the value help does"
- [ ] `POST DetailAttributes` and `POST SubcategoryAttributes` answer 405 `ENTITY_IS_READ_ONLY`, verified by test "does not allow creating attributes or assignments (@readonly)"
- [ ] A top-level `POST ProductDetails` (active or draft, any role) answers 422 `DRAFT_MODIFICATION_ONLY_VIA_ROOT`, verified by test "rejects a direct write to ProductDetails outside the product (lean draft)"
- [ ] `POST Products(<id>,IsActiveEntity=true)/details` with an assigned attribute answers 201 with `IsActiveEntity: true`, verified by test "creates a detail row of an active product through the product"
- [ ] The same with an attribute not assigned to the product's subcategory answers 400 `PRODUCTS_DETAIL_ATTRIBUTE_NOT_ASSIGNED` with target `attribute_code`, and an active `PATCH` of a row to such an attribute too, verified by test "rejects an attribute that is not assigned to the subcategory of the product (PRODUCTS_DETAIL_ATTRIBUTE_NOT_ASSIGNED)"
- [ ] The message is Russian under `Accept-Language: ru`, verified by test "reports the unassigned attribute in Russian"
- [ ] An unknown attribute code answers 400 `ASSERT_TARGET` on `attribute_code`, verified by test "rejects an unknown attribute code (@assert.target)"
- [ ] A row without an attribute or without a value answers 400 `ASSERT_MANDATORY` on the missing element (D4), verified by test "rejects a detail row without an attribute or without a value (@mandatory)"
- [ ] A second row for an attribute the product already has answers 400 `PRODUCTS_DETAIL_ATTRIBUTE_DUPLICATE` on `attribute_code` and writes nothing (D2), verified by test "rejects a second row for the same attribute of a product (PRODUCTS_DETAIL_ATTRIBUTE_DUPLICATE)"
- [ ] An active `PATCH` of `subcategory_code` on a product whose rows do not fit the new subcategory answers 400 `PRODUCTS_SUBCATEGORY_HAS_FOREIGN_DETAILS` on `subcategory_code` and keeps the stored subcategory (D1), verified by test "rejects a subcategory change of an active product whose details do not fit (PRODUCTS_SUBCATEGORY_HAS_FOREIGN_DETAILS)"
- [ ] A deep `POST Products` with two assigned rows answers 201 with both rows, a deep `POST` with a foreign row 400 `MULTIPLE_ERRORS` naming `subcategory_code` and the row, and `DELETE` of the product removes its rows, verified by test "creates a product with its details in one request and deletes them with the product"
- [ ] `viewer` reads `ProductDetails` and `Products(...)/details` with 200 and gets 403 on `POST`, `PATCH` and `DELETE` of a row through the product; `carol` gets 403 on `ProductDetails` and 200 on `DetailAttributes`, verified by tests "lets a CatalogViewer read details and forbids writing them" and "forbids a user without a catalog role to read details"
- [ ] A row posted into a draft (`POST Products(<id>,IsActiveEntity=false)/details`) and activated appears in the active rows, verified by test "adds a detail row to a draft and activates it"
- [ ] A draft `PATCH` of a row to an unassigned attribute answers 200, the next `GET` of the row and of the root carries one `PRODUCTS_DETAIL_ATTRIBUTE_NOT_ASSIGNED` draft message, and `draftActivate` answers 400 with the key and a target ending in `/attribute_code`, verified by test "reports an unassigned attribute on the draft row and rejects activation"
- [ ] A draft `PATCH` of a row to an attribute another row of the product already has writes `PRODUCTS_DETAIL_ATTRIBUTE_DUPLICATE` on the row and `draftActivate` answers 400 naming both rows, verified by test "reports a duplicate attribute on the draft row and rejects activation"
- [ ] A draft `PATCH` of `subcategory_code` to `MICE` on Laptop Pro 15 writes `PRODUCTS_SUBCATEGORY_HAS_FOREIGN_DETAILS` on the root's `subcategory_code` at once, `draftActivate` answers 400 `MULTIPLE_ERRORS` with the root message and one `PRODUCTS_DETAIL_ATTRIBUTE_NOT_ASSIGNED` per seeded row, and after the subcategory is set back activation answers 200 (D1), verified by test "reports detail rows that do not fit a changed subcategory on the draft and rejects activation"

## Decisions that require an ADR
- ADR-0026 "Product details as a composition of reusable attribute values" (accepted by the user on 2026-10-11, `docs/decisions/ADR-0026-product-details-composition.md`; decision 6 records D1 = (i)): the first composition and EAV shape of the model; reusable attributes through `SubcategoryAttributes` keyed by `cuid` with `@assert.unique.pair` in `db/`; value text plus unit; the explicit child projection with the root's `@restrict`; the navigation-path In parameter `product.subcategory_code` of the child row's value help; the three declarative set-membership rules with `exists ... $self` instead of handlers and instead of `@assert.unique` on the child; the subcategory-change behaviour of D1; the table section with the two parent side effects. Alternatives rejected there: reading (b), single-subcategory attributes, the composite key, the child referencing the assignment, the unmanaged association (compile error), the calculated element, the copied foreign key, handlers, `@assert.unique` on the child, containment, a field group, hiding Create, options (ii) and (iii).
- No new runtime or dev dependency, no `manifest.json` change, no change to authentication: no further ADR.

## Risks
- The navigation-path In parameter is source-read in UI5 1.153.0 (`ValueHelpDelegate` `requestProperty`), not yet measured in a browser; step 7 proves it with the narrowed dropdown of a new row and step 8 records the `$batch`. Detection: the dropdown lists all 20 attributes. Fallback (ADR-0026 alternatives): an on-read calculated element `subcategory_code = product.subcategory_code` on the child with a local In parameter, +1 contract property, re-measured figures, no other change.
- The late read of `product/subcategory_code` is one extra request per row when a dropdown opens; after `#SubcategoryChanged` or `#CategoryChanged` the rows are re-read, so a changed parent value is seen. Detection: step 8's `$batch` and the narrowed list after a subcategory change on a new product.
- Draft messages written by a failed Save stay on the rows until they are touched or the draft is saved (measured, #8 F1 behaviour); step 8 records it as known behaviour, not a defect.
- A child `POST` (inline Create followed by the attribute `PATCH`) writes the membership message on the `PATCH`, so the first feedback on a foreign choice comes after the choice; with the narrowed dropdown a foreign choice is only reachable before a subcategory exists (D5) or through the API.
- The `CategoryDropdown` page object matches the typeahead table by a property-based id regex; a table cell may render a different id shape. Step 7 probes it first and adds a page object only if needed; otherwise a duplicate is a review error.
- Test counts are expected values (173 + 20 + 2 backend, 52 + 6 UI); each gate re-derives them and quotes its own.
- Contract figures per phase: phase 2 1177, phase 3 1273 measured with the exact annotation set of research section 6, which has no `UI.Importance`; SCREENS adds `#High` on the Attribute column, so phase 3 is expected at 1274 and the gate quotes the fresh count. The contract grows by 389 lines (44%) for three entity sets with drafts and texts; acceptable for the first composition, recorded in CHANGELOG.
- CSV quoting: a bare `"` as a value breaks the file silently (measured on the scratch, every `attribute` expand was `null`); the inch unit is `in` (user, 2026-10-11), so no `""""` spelling is needed and the deploy check of step 2 reads `in` back; the fact goes to LESSONS.
- `cds add data` would edit the protected `mta.yaml`; the CSVs are written by hand.
- Mock mode (`npm run start-mock`) needs the four JSON files to show the section and resolves the composition through the metadata's referential constraints; it is not a gate and does not serve `ru`.
- No change to what any endpoint answers to an unauthenticated caller: the new sets sit under `@requires: 'authenticated-user'`, so the CI readiness probe, the `run-app`/`test-all` smoke curls, the `ui-verifier` server check and the README need no authentication update.
- `importProducts` is untouched; a workbook cannot carry details (follow-up issue if wanted).
