## Decisions that require an ADR
- ADR-0022 `docs/decisions/ADR-0022-pipeline-metrics.md` (proposed): (1) the definitions D1-D13 as the single way to measure time, tokens, cost, phase and rework; (2) the Claude Code transcript is read only through `scripts/lib/transcript-usage.mjs`, tested on a synthetic fixture and self-checked against `cost-state`, while hooks are the sanctioned source of markers; (3) the event log `.pipeline/metrics-<session>.jsonl` with the record shapes of `research/data-flow.md`; (4) what is committed: `docs/metrics/history.jsonl` and the `## Cost` section of `SUMMARY.md`, raw data stays in `.pipeline/`; (5) non-goals: OpenTelemetry (later, cross-check only), dashboards or pages, per-user analytics. ## Risks
- The transcript format is internal: a Claude Code update can rename a field and the fixture test stays green. Detection: the card prints the `version` of the records and warns loudly when a session parses to zero requests or when the `agent-stop` aggregate written live differs from a re-parse by more than 1%; `reconcile` shows the drift per kind. `upstream-watcher` notes the Claude Code version at each check (open item for a later change).
- Transcripts age out after 30 days (Claude Code `cleanupPeriodDays`): the baseline (step 5) runs before 2026-10-10 or `catalog-authorization` loses its second session; `history.jsonl` is the durable record from then on.
- Hooks load at session start: the `/feature` session that edits `settings.json` sees no live records; step 11 needs one restart, stated in the step.
- The reconciliation gap (27% with the verified 5m/1h prices, 12% when every cache write is priced at 1h) may not close: v1 explains it per kind and shows `unattributed`; if step 4 finds a transcript field that changes D1 or D2, `architect` amends `research/definitions.md` and the ADR before step 6 pins the fixture.
- `Phase:` is free text today (`none (products-excel-upload #7 done ...)`): the marker parser takes the first integer 0-7 and step 10 fixes the format in the skill; a `none` marker at phase 7 is correct, not a defect.
- This feature's approved plan `c10c4f0` numbers its phases before the renumbering (2-4 implementation, 5 verification, 6 review, 7 documentation) while the markers from 19:02:47 on use the skill's numbers; D12 compares them as written (user decision 2026-09-30), so step 11's `test-backend` under the old marker `5` is planned, step 11e's `test-backend` in phase 4 is rework, and `reviewer` and `docs-keeper` stay in their home phases; a launch in the seconds before the orchestrator's `Phase:` edit takes the previous phase (19:02:35 and 19:02:44, two rework launches). Both are stated in `SUMMARY.md`, not corrected.
- Concurrent sessions overwrite `.pipeline/current-session`: every CLI command accepts an explicit id; the file is a convenience only.
- Prompt budget: steps 9-10 grow four budgeted files; the re-record is a listed action with a CHANGELOG line, not a surprise at the gate.
- Privacy: an event log record with prompt text or tool output would leak conversation content into `.pipeline/` (gitignored, but read by `/retro`): the sentinel test and the reviewer's check guard it.
- SubagentStop already runs eslint (up to 150 s); the added parse of a 1-3 MB transcript is under a second, and the record is written before the checks so a blocked stop still records; the hook timeout (180 s) is unchanged.
- Pricing drift: the table is dated and sourced; the pricing self-check warns when `cost-state`'s own tokens priced with the table diverge from its `costUSD` by more than `PRICING_TOLERANCE` (5%) for a model, which is the signal to re-record the table.

## Open questions
1. Idle threshold: recommended two caps, a turn gap at 5 min and a tool gap at 10 min (the Bash tool's maximum timeout; `npm test` and `test:ui` runs then count in full); alternative: the prototype's single 5-minute cap. Step 4 reports #7 under both so the difference is a measured figure before the choice is final.
2. Committed artifacts: recommended both, `docs/metrics/history.jsonl` (machine-readable, `compare`) and the `## Cost` section of `SUMMARY.md` (human-readable, survives the prune and the issue comment); alternative: `history.jsonl` only, with `SUMMARY.md` linking to it.
3. Briefing: recommended one line from the last history entry (feature, cost, active time, rework share) and no regression warning in v1 (`compare` on demand; a threshold needs three comparable features first); alternative: warn when cost exceeds the previous feature by a factor of 1.5.
4. Reconciliation: recommended that v1 accepts a documented gap (73% recovered today with the verified 5m/1h prices; 88% when every cache write is priced at 1h) once step 4 names the cause per kind and the card shows `unattributed`; reconciliation to 98% is not a gate because auxiliary calls (H1) cannot be attributed to an agent by construction; alternative: make 95% recovered a phase 2 gate criterion, at the risk of blocking on Claude Code internals. Decided: the documented gap is accepted (plan gate, 2026-09-29); after step 4 showed the ratio is structurally 62-97% in auto mode with subagents, the user moved the warning to the pricing self-check (`PRICING_TOLERANCE` = 0.05 per model, 2026-09-29), and the recovered ratio and `unattributed` stay on the card as information.
5. OpenTelemetry: recommended later, as a cross-check only, once a collector exists; it adds no per-agent or per-phase attribution and costs an exporter and a collector.
6. Feature join key: recommended `gitBranch` on every record plus the `/spec` prompt marker for sessions on `main` (covers history without any new agent instruction); alternative: the STATE `Feature:` marker only (no history, no `/spec` attribution).
7. Retention of `.pipeline/metrics-*.jsonl`: recommended 30 days, aligned with Claude Code's transcript retention; alternative: 14 days like the MCP audit.
8. Baseline scope: recommended #5, #6, #7 and `catalog-authorization` (transcripts present, current skill shape); alternative: #5-#7 only.
9. Which plan D12 reads: recommended the final plan (the working tree while in work, the `SUMMARY.md` permalink commit after the prune), under which steps added by an amendment count as planned and a re-entered phase shows only in rounds; alternative: the plan as approved at the plan gate, the first version in the path's full git history whose `Status:` begins with `approved` (`research/definitions.md` D12), under which amendment steps count as rework. Decided: the plan as approved at the plan gate (user, 2026-09-30): fix-round steps such as 11a-11e count as rework when their agent type is not planned in that phase of the approved plan (#7: 4 rework launches instead of 1; this feature: 3 of the first 12).
