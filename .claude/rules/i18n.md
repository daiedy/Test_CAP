# Texts and translations

## Files
- `_i18n/i18n.properties` (en, default) and `_i18n/i18n_ru.properties`: model labels, keys `<Entity>.<element>` and `<Entity>` for the entity name.
- `_i18n/messages.properties` and `_i18n/messages_ru.properties`: `req.reject` messages, UPPER_SNAKE keys: `PRODUCT_STOCK_NEGATIVE`.
- `app/<app>/webapp/i18n/i18n.properties` and `i18n_ru.properties`: application texts, keys `<page>.<element>.<property>`, plus `appTitle`, `appDescription`.

## Rules
- Every new key is added to both locales (en and ru) at once. There are no empty translations.
- Texts that a UI5 control or Fiori Elements renders itself are framework texts, not project keys: they ship translated in `sap/m/messagebundle*.properties` and `sap/fe/**/messagebundle*.properties` (for example the `sap.m.ObjectMarker` texts `OM_DRAFT`, `OM_LOCKED_BY`, `OM_LOCKED_BY_ANOTHER_USER`, `OM_UNSAVED_BY` behind `@Common.SemanticKey`, ADR-0015, and the draft dialog texts `C_TRANSACTION_HELPER_*`). Check the bundle of the loaded UI5 version before adding a key: a purely declarative change can satisfy invariant 7 by adding nothing.
- Do not rename keys without searching the repository (`grep -r '<key>'`).
- Placeholders `{0}`, `{1}` for the arguments of `req.reject(400, 'KEY', [a, b])`.
- Text type comments before the key per the SAP convention: `#XTIT`, `#XFLD`, `#XMSG`, `#XBUT`, `#YDES`.
- UTF-8 encoding, one key=value pair per line, no BOM.

## After editing
- `cds compile srv --to json` without warnings about missing keys (when the key is used in `@title`).
- For the UI: restart `npm start` and check the screen in both locales (`sap-ui-language=ru`).

## Forbidden
- User-facing strings in CDS, JS, XML bypassing i18n.
