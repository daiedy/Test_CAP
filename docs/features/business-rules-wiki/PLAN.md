## Risks
- GitHub renders the YAML frontmatter raw on wiki pages (not measurable before the first page exists): step 0 measures it on the hand-made Home page; if raw, step 2 adds `export <dir>` and step 4 runs it before the action, and step 5 compares a mirrored page with its export and its source. The repository view renders frontmatter as a table either way. Measured raw at step 0 (CONTEXT "User decisions").
- `workflow_dispatch` needs the workflow file on `main`: the one-file pull request of step 4 is a user action with CI on it (chosen at the plan gate, CONTEXT "User decisions" Q9); if the pull request is delayed, step 5 moves after the final merge and `VERIFICATION.md` is committed in a follow-up.
- The default `github.token` cannot push to the wiki: the action README says `contents: write` suffices for the same repository; the first dispatch runs with `dry-run: true` and prints the remote URL, the second pushes; a 403 means a PAT secret, which is a user decision before any token is created.
- `strategy: init` force-pushes the wiki repository on every run: intended (read-only mirror), stated in the footer and in the ADR; a page created by hand in the wiki UI is lost at the next sync.
- The backfill is large for one `docs-keeper` run (67 pages, `maxTurns` 80): split into six launches (3a-3f) by folder, each writing pages from the first turn; the orchestrator resumes a stopped launch with SendMessage ("continue from page N"); `audit` shows the remaining gaps after each launch, which is the progress measure.
- Rule pages drift from the code without anyone noticing: the `verified` stamp and `audit` catch a changed `code` file and an unreferenced message key or element in CI, `/test-all` and the phase 6 gate; a Stop advisory is not part of this feature (CONTEXT "User decisions" Q8) and can follow later. A page that lists a whole folder in `code` is confirmed too often and tells nothing: the reviewer rejects `code` entries broader than a file or a `*.cds` glob of one folder.
- `audit` loads the CDS model (`cds.load('*')`, about 1 second) in CI and in `/test-all`: measured at the phase 2 gate; it does not run in the Stop gate or in the PostToolUse hook.
- Two agents assign the same rule id in parallel: `next-id` reads the committed pages; the uniqueness check of `wikiStatus` (duplicate ids are a shape finding) fails `check-docs-fresh.mjs` at the next Stop or in CI.
- `docs/wiki/**` generated files are not protected paths: a hand edit with an intact header passes `check-docs-fresh.mjs` until the next regeneration; `test/wiki.test.js` byte-compares them at every `npm test` (the ADR-0029 choice for `docs/api/**`).
- The 6 `@assert` constraints remain absent from `DOMAIN-MODEL.md` (`annots()` prints `@assert.` keys only): out of scope here, listed as a follow-up for `gen-registry.mjs` in `SUMMARY.md`; the wiki's rule pages and `audit` cover them.
- `test/prompt-budget.json` grows for the protocol, `docs-keeper`, the `feature`, `gen-docs` and `test-all` skills and the new rule: the ratchet is raised by this feature's plan gate (ADR-0018 asks for a retro decision; noted in CHANGELOG); the protocol addition is three lines and the rule file is new.
- The wiki is public: it shows business rules and entity descriptions already visible in the public repository; no secret or credential appears in a page (the reviewer checks `code` paths and links).
