Facts from `docs/features/products-validations/research/validation-facts.md` (scratch probes P0-P14, Q1-Q4 on 2026-10-13; A1-A38 on 2026-10-14 under `~/.claude/jobs/<job>/tmp/pv-scratch`, deleted):

- `@assert.format.message: 'KEY'` and `@assert.range.message: 'KEY'` (and `@mandatory.message`) take a bare message key from `_i18n/messages*.properties`, localized (ru measured); the error `code` stays `ASSERT_FORMAT`/`ASSERT_RANGE`. Open bounds `[(0), max]` work (`Validation.Exclusive` +2 EDMX lines; `Validation.Pattern` +1 per `@assert.format`).
- Timing: format/range/target messages are in the draft `PATCH` response; `@assert: (case ...)` messages are written at commit for **touched** elements (`cds.env.features.assert_touched_only`) or elements named as `additionalTargets`, visible on the next `DraftMessages` GET; at activation input validation (`ASSERT_*`) rejects first and the constraints never run in that request (two Save rounds possible). Deleting a child (a selection) touches no value row: a rule that depends on it fires at Save only. A draft message keeps the text of the locale of the request that wrote it.
- `error('KEY', args, ('field1', 'field2'))` in a constraint `then` branch (`@cap-js/db-service` `cql-functions.js`, parsed by `assert.js`) gives `target` + `additionalTargets` (+ message args); **not in capire docs**; targets must be string literals (a path is cut to its last segment, a generated FK name is a compile error in annotation expressions). `args` may be paths of the row: `attribute.name`, and `coalesce(attribute.localized.name, attribute.name)` gives the request-locale text or the base text (`localized.x` alone is null when the locale has no texts row). On the active path the OData error shows `target` only.
- Subqueries are not allowed in annotation expressions. Uniqueness on a draft root: a self-association in `db/schema.cds` with functions in the ON (`lower(trim(...))` compiles) + `exists namesakes`; from a draft it resolves to active rows, the own row is excluded by `ID`; `@cds.api.ignore` does not hide a navigation property (+5 EDMX with a title).
- `$self.<value>` compared with the filtered entity's columns inside an infix filter works (`exists attribute.subcategories[... and $self.numberValue < minValue]`), as does `numberValue not in (1, 2, 4, ...)`; a path through two to-many associations then a filter (`not exists product.details.selections[value.enables.code = $self.attribute.code]`) and the nested `exists a[exists b[...]]` both work.
- A rule between two child rows must start at the draft row (`exists product.details[attribute.code = $self.attribute.atLeast.code and numberValue > $self.numberValue]`); an association that starts at an entity outside the draft tree (a backlink `DetailAttributes.rows`) resolves to the **active** rows while editing a draft (lean draft) and only fires at Save.
- `matchespattern(x, pattern)` is a portable CAP function (capire "Standard Functions"); SQLite maps it to `regexp` = JS `RegExp`, HANA `LIKE_REGEXPR`; it works in an `@assert` branch with a column as the pattern (draft PATCH stores the value and reports). R9 was withdrawn by the user, the fact stays in ADR-0028 alternatives.
- `sap.common.Currencies.minorUnit` exists and `@sap/cds-common-content` 3.2.0 ships it (33 currencies with 0, e.g. JPY); `floor(price) != price` is the portable "has decimals" test. The project EDMX has no `Common.UnitSpecificScale`/`CodeList.CurrencyCodes`; the UI5 currency type reads them only with both annotations (+10 EDMX), browser proof pending.
- EDMX: a managed association to a code list costs +28 lines (its generated `Common.ValueList` block; `@Common.ValueList: null`, `viaAssociation: null`, `@cds.odata.valuelist: false` on the element do not remove it); a to-many backlink with a title +5; two Decimal elements with titles +8; `description @Common.FieldControl: (stock > 0 ? 7 : 3)` +10.
- Handlers on lean draft: `before('SAVE', Products)` fires on a deep `POST` (`CREATE`) and at `draftActivate` (`UPDATE`) with `req.data.details` present; `before('PATCH', ProductDetails.drafts)` rejecting with 400 stores nothing.
- Every new root constraint needs a per-row import pre-check (ADR-0021 4E shape); a child constraint the import never writes needs none.

**Why:** the issue assumed `@assert.unique` and cds default texts; the measured toolkit (custom keys, `error()` targets and args, self-association, `$self` in filters, draft-tree scoping) decides the whole #10 design and the user's "prevent before validate" principle ([[feedback-prevent-before-validate]]).

**How to apply:** check ADR-0028's status before reusing; quote the EDMX costs; for a rule across two edited fields use `error()` with both targets; for a rule between rows start at the draft row; never promise draft feedback for `@mandatory` or for a deleted child.
