# products-details-section: verification

Date: 2026-10-12. Agent: `ui-verifier`. Server: `npx cds serve --in-memory --port 4004` from the worktree root.

Verdict: defects found: D-1 (open, goes to `architect`). Scenarios 1-10 completed; every other PLAN browser expectation held. Not "ready for review" until D-1 is decided.

D-1: Scenario 6 (new product, D5), Create a row before a subcategory exists, open the Attribute dropdown. Expected: the full attribute list (SCREENS: 20 attributes). Observed: 45 entries with repeated names (Colour 11x, Material 9x, Weight 3x, Capacity 3x, Battery Life 2x, Connectivity 2x, Power 2x), because the value help reads `SubcategoryAttributes` (45 assignment rows) without a `$filter` when `product/subcategory_code` is empty. Screenshot `screenshots/s6-dropdown-unfiltered-duplicates.png`. Request: `GET SubcategoryAttributes?$select=ID,attributeName,attribute_code,subcategory_code&$count=true&$orderby=attributeName&$skip=0&$top=100` (reqid 223, `@odata.count` 45). Every duplicate carries the same `attribute_code`, so no wrong data is stored; the effect is a confusing list on the rare path (row added before a subcategory is chosen).

The late `GET .../details(...)?$expand=product($select=subcategory_code)` that the plan expected was not sent in scenarios 2 and 5: the narrowed dropdown request carried `subcategory_code eq 'MICE'` without it (the value was taken from the already loaded draft parent). Failed requests (status >= 400): the known sandbox 404s (`/appconfig/fioriSandboxConfig.json`, `/sap/bc/lrep/flex/settings`, `/sap/bc/ui2/flp;sap-metrics-only`) and the expected inner 400s of the failed Saves above; no unexpected 4xx/5xx.
