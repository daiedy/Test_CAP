## Risks

| Risk | Detection |
|---|---|
| The column header falls back to something other than "Rating" if `Label` is omitted on the `DataFieldForAnnotation` (FE builds the header from the record, not from `@title`) | Explicit `Label` in row 3; OPA5 `iCheckColumns` by header at the phase 4 gate |
| The `targetAnnotation` string of the `FieldIdentifier` for a DataPoint field is not confirmed by the sources read | `test-ui` derives it from the rendered `FormElement` id; fallback a custom page object matching `sap.m.RatingIndicator` in the `GeneralInfo` form container (row 4) |
| The raw snapshot diff of phase 3 shows about 72 added and 56 removed lines because of a positional move of the `Common.SemanticKey`/`SideEffects`/`Messages` block, not 16 | `reviewer` reads the diff for content (`research/contract-delta.md`); the contract test asserts the records |
| A draft `PATCH` with 6 answers 200 (`DraftMessages`), only `draftActivate` answers 400; a test written against the `PATCH` status would be red | The draft test asserts activation (row 2, TESTING "cds 10 specifics") |
| `mockdata/Products.json` without `rating` makes `sap-fe-mockserver` invent values or show empty stars | Row 3 adds the values; verifier scenario "Mock mode" |
| The verifier's edit scenario leaves a draft or a changed rating, which breaks `iCheckRows(15)` and the seeded-value assertions of a later OPA5 run | Verifier restores `Laptop Pro 15` to 5 and discards drafts (row 5); OPA5 runs start from a fresh `cds serve` |
| The CDN UI5 version is unpinned (ADR-0006): the edit-style fact is verified on 1.152.0 and a later version could render the form field differently | Verifier scenario "Editor changes the rating"; `upstream-check` reports the version change |
| `@assert.range` does not reject `null`, so a product created without a rating shows empty stars, which a user could read as "0 stars" | Accepted under the recommended default (open question 2); switch to `@mandatory` or a default only on the user's answer |
| Settled by `SCREENS.md`: the column carries `#Low`, so on a narrow window it is the first to move into the pop-in; this is intended, but a user may miss the stars on a tablet | `ui-verifier` `SCREENS.md` scenario G (about 700 px and 400 px) records the pop-in order; `SCREENS.md` open question 1 offers "no importance" |
| `search_model` or the registry is stale after phase 2 (new element not visible to phase 3 agents) | `npm run docs:registry` at the phase 2 gate (PostToolUse marks it stale); phase 3 agents run `search_model` on `CatalogService.Products` before editing |
