# ADR-0021: Import products from an Excel workbook

Date: 2026-09-25. Status: accepted (user, 2026-09-25, feature `products-excel-upload`).
<!-- On acceptance replace the whole Status sentence with the accepted form; never append to the proposed one. -->

## Context
GitHub issue #7 asks for creating products on the List Report by uploading an Excel file. Fiori Elements V4 has no standard table action that imports rows from a file (checked at the plan gate on 2026-09-25, research section 3): the standard spreadsheet features are Export and clipboard paste, and the Upload Table building block stores attachments. `PATTERNS.md` has no row for a file upload, for parsing a file, for a bulk create, or for adding a runtime npm dependency, so five decisions are open (issue #7 "Scope hints"): (a) where and with what the workbook is parsed, (b) how the file travels to the server, (c) how rows are created on the draft-enabled `CatalogService.Products` and which declarative checks still fire, (d) all-or-nothing versus partial import, (e) duplicates by `name`. Facts behind the options (package versions, advisories, framework documentation) are in `docs/features/products-excel-upload/research/import-mechanism.md`.

## Decision
1. **Parsing on the server with `read-excel-file`** (`read-excel-file/node`, MIT, ESM, read-only, 9.3.10, four small dependencies, no known advisory on 2026-09-25) as a new runtime dependency in `package.json`. The fixture workbooks of the tests are written with `write-excel-file` (same author, MIT, one dependency) as a devDependency. The parsing and the column mapping live in `srv/lib/products-import.js` (pure functions, no `req`), unit-tested.
2. **Transport: an action bound to the `Products` collection**, `action importProducts(in: many $self, file: ProductsImportFile not null) returns Integer` inside the `Products` projection of `srv/catalog-service.cds`; `ProductsImportFile` is a service type `{ content: LargeBinary @Core.MediaType: mediaType; mediaType: String(100) @Core.IsMediaType; fileName: String(255) }`, the shape Fiori Elements V4 documents for "File upload as action parameter". A collection-bound action is the bound variant for a set (PATTERNS "Action on a set or without context": unbound only if a bound one is impossible); it inherits `@restrict` of `Products` (`grant: '*'` to `CatalogEditor`, `READ` only to `CatalogViewer`), so no new authorization annotation is written.
3. **Rows are created active, one `INSERT` per row inside the action's transaction** (`this.run(INSERT.into(Products).entries(row))` in the `on('importProducts', Products)` handler of `srv/catalog-service.js`), so the generic input validation of the service (`@mandatory`, `@assert.range`, `@assert.target`) runs for every row and its error is attributed to the row number. No draft is created. The handler adds only what no annotation expresses: the workbook structure (header row, unknown or missing columns, cell types), the row limit, and duplicate names. This rests on a fact that the documentation does not state for internal calls; phase 2 measures it first (PLAN step 3), and if a declarative check does not fire on the internal `INSERT`, work stops and this ADR is revised; the check is never re-implemented in the handler.
4. **All-or-nothing with a complete row report**: every row is checked, the first collected message is `PRODUCTS_IMPORT_NOTHING_IMPORTED`, then every failure follows as `req.error(400, 'PRODUCTS_IMPORT_ROW_INVALID', [row, column, reason])` (or `PRODUCTS_IMPORT_DUPLICATE_NAME`), with no field `target` and no cap on the number of messages; if any was collected the request fails with one 400 listing all of them and the transaction rolls back, so nothing is written. A clean file creates all rows and answers the number of created products plus an info message `PRODUCTS_IMPORT_DONE`.
5. **Duplicates by `name` are row errors** (`PRODUCTS_IMPORT_DUPLICATE_NAME`): a name repeated inside the file, or equal to the name of an existing active product (case-insensitive, trimmed). This is imperative because the model has no uniqueness constraint (ADR-0015: the semantic key implies none) and adding one is outside this feature.
6. **UI: the Fiori Elements action parameter dialog** renders the upload. `app/products/annotations/Products.cds` adds a `UI.DataFieldForAction` for `CatalogService.importProducts` labelled "Import from Excel" (user decision; ru U+0418 U+043C U+043F U+043E U+0440 U+0442 U+0020 U+0438 U+0437 U+0020 Excel, "Import iz Excel") to `UI.LineItem` (table toolbar), hidden for a non-editor by `![@UI.Hidden]` on the record with the `$edmJson` `$Not` `$Path` to `/CatalogService.EntityContainer/Permissions/isEditor` (the singleton of ADR-0013, a fourth consumer next to `UI.CreateHidden`/`UpdateHidden`/`DeleteHidden`); no `manifest.json` change, no controller extension, no fragment. Whether UI5 1.152 renders a file field for a collection-bound action parameter is measured in phase 3 before the OPA5 work (PLAN step 8). **Fallback, only if that measurement fails:** a controller extension `app/products/webapp/ext/controller/ProductsListExt.js` registered and wired to a table-toolbar button via Fiori MCP (PATTERNS "Client-side logic"), opening a `sap.ui.unified.FileUploader` dialog fragment and calling the same action through `editFlow.invokeAction(..., { skipParameterDialog: true })`; the backend does not change.
7. **Workbook contract**: the first sheet, the first row is a header row with the element names `name`, `description`, `price`, `currency`, `stock`, `category`, `rating`, `imageUrl` (case-insensitive, any order; each missing mandatory column `name`, `price`, `currency`, `stock`, `category` gives its own `PRODUCTS_IMPORT_MISSING_COLUMN`; missing optional columns are allowed; unknown columns give `PRODUCTS_IMPORT_UNKNOWN_COLUMN`); `currency` and `category` hold codes (`USD`, `ELECTRONICS`), never localized names; empty rows are skipped; at most 1,000 data rows per file (`PRODUCTS_IMPORT_TOO_MANY_ROWS`); no data row gives `PRODUCTS_IMPORT_EMPTY`; a payload that is not an xlsx workbook gives `PRODUCTS_IMPORT_NOT_XLSX`. Only `.xlsx` is accepted (`Core.AcceptableMediaTypes`). The format hint lives only in the file field label and in `README.md` (user decision).

## Amendment: list refresh and required file (user decisions 2026-09-25, phase 3)
The phase 3 measurement of decision 6 (`docs/features/products-excel-upload/research/import-mechanism.md` 6.2, 6.3; framework facts in section 7) found two gaps. The user decided to close both declaratively; decision 6 and its fallback stay as written, no `manifest.json` change, no controller extension, ADR-0007 untouched.

A. **Refresh after the import.** Fiori Elements V4 (UI5 1.152) does not refresh the List Report after `importProducts`: the server holds 18 rows, the table keeps 15 and sends no `GET` (6.3). Fiori Elements refreshes by itself only after create, delete, the draft actions and a bound action whose returned instance differs from the bound one; `importProducts` returns `Integer`. `app/products/annotations/Products.cds` annotates the action with `@Common.SideEffects: { TargetEntities: ['/CatalogService.EntityContainer/Products'] }` (`annotate CatalogService.Products with actions { importProducts @Common.SideEffects: {...}; };`), the absolute entity-set path of the fiori-mcp "Side Effects" samples 7 and 9. Measured by the step 8 probe: Fiori Elements adds one `GET Products?$count=true...` to the action's `$batch`, and the table shows 18 rows before the result message box is closed. It is a refresh hint for the client, so it lives in the presentation layer (`app/`). New PATTERNS row "Refresh after an action".

B. **Required file.** The action dialog shows no required marker and an empty submit does nothing (no request, no message, 6.2), because Fiori Elements 1.152 reads the requiredness of an action parameter only from the parameter's `Common.FieldControl`; `Nullable="false"` from `not null` is ignored, and so is any annotation on the stream element `content` (research 7.2). `srv/annotations/Products.cds` adds `@mandatory` to the parameter `file` (PATTERNS "Mandatory field", semantic layer, CLAUDE.md invariant 5); CAP emits `Common.FieldControl: #Mandatory` on the parameter. The framework then marks the label required and, on Import from Excel with no file, sets the file field to value state Error with its own text (`Upload a file for "Excel File (.xlsx)".`, translated by UI5), keeps focus in the dialog and sends nothing; choosing a file clears the state. No project text is added. What the server answers to a request without `file` after the annotation is measured in phase 3 (research 6.5) and pinned by a backend test.

## Alternatives
| Option | Why rejected |
|---|---|
| Standard Fiori Elements clipboard paste (table-level paste creates rows) | Not a file upload; documented for draft-enabled tables with `creationMode` `Inline` or `InlineCreationRows` and enabled by default on Object Page tables, not for the List Report of a draft root; the front end checks data types only, rows go in one `$batch` with no all-or-nothing row report; columns with `TextOnly` text arrangement (our `category`) cannot be pasted |
| Fiori Elements "Upload Table" building block | Stores one file per row of an attachments entity with an `Edm.Stream` property (`UI.MediaResource`); it does not create business rows from a file's contents |
| `xlsx` (SheetJS) from npm | The npm registry stops at 0.18.5, which carries two high advisories (GHSA-4r6h-8v6p-xvw6 prototype pollution, GHSA-5pgg-2g8v-p4x9 ReDoS, fixed only in versions published outside npm) |
| `exceljs` | Last stable release 4.4.0 of 2023-10-19, nine dependencies incl. `archiver`, `unzipper`, `tmp`; reads and writes, far more than needed |
| Community UI5 library `ui5-cc-spreadsheetimporter` (parse in the browser, post through OData) | The app's first third-party UI5 library (deployment, CSP, `ui5lint` scope); it bundles SheetJS from a CDN tarball; it creates rows one OData request at a time, which on a draft root means drafts or per-row activation and no all-or-nothing transaction; the checks run in the browser and on the server twice |
| Bare client-side parsing in a controller extension | UI5 ships no xlsx reader (`sap.ui.export` only writes), so a third-party library lands in the browser anyway, and the server still needs the row checks |
| Unbound action | Loses the inheritance of `@restrict` on `Products` (a separate `@requires: 'CatalogEditor'` would be needed) and is the PATTERNS second choice when a bound one is possible |
| Custom express route (`cds.on('bootstrap')`, multipart) | Leaves OData: no `@restrict`, no localized `req.reject` messages, no Fiori Elements integration, a second auth path to maintain |
| One multi-row `INSERT.entries(rows)` | A failing check aborts on the first error or reports targets without a row number (not measured); per-row inserts give the row report of decision 4 at a cost acceptable for 1,000 rows (measured in phase 2) |
| Create drafts (`srv.new(Products.drafts)`) | Drafts skip `@mandatory` and `@assert.*` until activation (ADR-0012, TESTING "cds 10 specifics"), leave up to 1,000 drafts owned by the user in the List Report and need a second step to activate |
| Partial import (good rows written, bad rows reported) | A corrected file re-uploaded creates the good rows twice; the user has to edit the file down to the failed rows |
| `@assert.unique` on `name` | A database constraint that changes the existing Create and Edit behavior and answers with a database error, not a user message; outside this feature |
| Localized column headers or localized category and currency names | A file becomes language-dependent; a Russian user's file fails for an English user; codes are what the model stores |
| Amendment A: return the created products (`returns many $self`) so that Fiori Elements refreshes by default | Changes the phase 2 contract (value count, tests); the default refresh is documented for a bound action returning a different instance, not for a collection-bound action; one declarative annotation does it |
| Amendment A: controller extension that refreshes the table after the action | Imperative, needs an extension and a manifest change through Fiori MCP for what an annotation expresses (CLAUDE.md invariant 6) |
| Amendment A: `TargetEntities` relative to the binding parameter (`in`) | Not documented for a collection-bound action; the absolute path is documented (samples 7 and 9) and measured |
| Amendment B: controller extension that checks the file before the action (PATTERNS "Client-side logic") | Imperative, a manifest change and new OPA ids, for a check the framework already runs behind one annotation |
| Amendment B: `@Common.FieldControl: #Mandatory` written directly on the parameter | Same EDMX, but `@mandatory` is the PATTERNS way and also states the rule for the server |
| Amendment B: `@mandatory` or `not null` on `ProductsImportFile.content` | Fiori Elements reads the field control of the parameter, not of the stream element of its type (research 7.2) |
| Amendment B: keep the framework behaviour (no marker, silent empty submit) | Rejected by the user, 2026-09-25 |

## Consequences
- New runtime dependency `read-excel-file` and devDependency `write-excel-file`: `package.json` and `package-lock.json` change once, in a session the user starts with `PIPELINE_ALLOW_PROTECTED=1` (`package-lock.json` is protected); Dependabot then watches both.
- First `srv/lib` module and first `_i18n/messages*.properties` keys; first custom action and first `UI.DataFieldForAction` of the project.
- The OData contract grows by the action, the complex type and the annotations; the snapshot and `metadata.xml` are regenerated in phases 2 and 3.
- The request body of a 1,000-row file must fit the body-parser limit of 100 KB (CAP default); phase 2 measures the base64 size of the 1,000-row fixture and, only if it does not fit, sets `@cds.server.body_parser.limit` on `CatalogService`.
- `PATTERNS.md` gains the rows "File upload through an action" and "Bulk create from a file" (examples: this feature), "Action on a set or without context" gets the example `importProducts`, "Role-aware UI visibility" lists `UI.Hidden` on a `DataFieldForAction` record, "Dependency update" gets a sentence on adding a dependency (ADR plus the protected-file session). `CONVENTIONS.md` needs no change.
- A second instance of the known UI5 1.152 `$select` TypeError for the container-qualified `$Path` (STATE open debt) may appear; `ui-verifier` records it against the known noise.
- Amendment: the phase 3 contract also gains the `Common.SideEffects` record of the action and the `Common.FieldControl` of `file` (look-ahead +19 −0 lines of `metadata.xml` against the phase 2 commit `1a1199f`, research 7.3). `PATTERNS.md` gains the row "Refresh after an action" and the action-parameter case in "Mandatory field" (written with this amendment; the example cells are filled by the steps that apply them). `docs/LESSONS.md` records that a Fiori Elements V4 action parameter is required only through `Common.FieldControl`.
