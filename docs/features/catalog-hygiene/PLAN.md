# catalog-hygiene: plan

Date: 2026-10-09. Status: approved 2026-10-09. Gate mode: autonomous.

Shape (ADR-0018): one criterion per line under "Acceptance criteria", table rows only under "Steps"; explanations belong in `CONTEXT.md` or `research/`. `node scripts/check-feature-docs.mjs <name>` verifies the shape at the phase 1 gate.

Contract rule: a step that changes the OData model (`db/*.cds`, `srv/**/*.cds`, `app/*/annotations/*.cds`) schedules `npx vitest -u` and `cds compile '*' --to edmx-v4 -s CatalogService -l en > app/products/webapp/localService/metadata.xml` in the same phase, never in a later one; the sync test in `test/metadata.test.js` turns red at that phase's gate otherwise (PATTERNS "OData contract").

Scope of this plan (GitHub issue #20, P1): three one-line CDS edits, five new backend tests, two updated contract assertions, one browser verification, and the documentation that closes three `docs/STATE.md` open-debt rows. Measured on a scratch copy (`research/contract-delta.md` section 1): the price precision changes 1 EDMX line, `@assert.target` on `currency` changes none, the short singleton path changes 7; the issue's "all three change the contract" holds for two. The model changes fall into two phases of the `/feature` workflow (phase 2 backend, phase 3 UI annotations), so the contract rule schedules one regeneration per phase with its own figure; Open question 4 offers the single-regeneration alternative. No `SCREENS.md`: no screen, field, action or state changes, only an annotation path and two validations; the `ui-verifier` scenarios V1 to V3 are spelled out in the acceptance criteria instead.

## Decisions that require an ADR
- No new ADR is proposed: the three changes apply decisions already taken. The price precision is the ADR-0003 rule itself ("Money: `Decimal(15, 2)`"), only its historical exception is withdrawn; `@assert.target` on `currency` follows the PATTERNS row "Association target existence check" with `Products.category` as the example; the short singleton path is the fallback ADR-0013 part 8 names and capire documents.
- ADR-0003 amendment (step 2, recommended answer to Open question 2; the alternative is a new ADR-0024, see there). Proposed wording: "`Products.price` becomes `Decimal(15, 2)` as the rule above says; the historical exception is withdrawn. No data migration was needed: the development database is SQLite in-memory loaded from `db/data/my.catalog-Products.csv`, whose values fit unchanged, and HANA is not configured (STATE open debt), so the first productive deployment creates the column at (15, 2). `@assert.range` on `price` stays `[0, 99999999.99]` as a business bound independent of the storage precision" (or the widened bound, per Open question 1). The `Status:` sentence stays `accepted.`: amendments never append to it (`templates/adr.md`), and the template's `superseded by` form retires a whole ADR, which would wrongly retire the other five rules of ADR-0003.
- ADR-0013 amendment (step 10, `docs-keeper`, no user decision): records the measured outcome of the short path (TypeError gone or not, hidden state on both pages) so that the ADR and the PATTERNS row agree.

## Risks
- The short path removes the TypeError by reasoning (a valid absolute OData V4 binding path, `research/contract-delta.md` section 2), not yet by measurement. Detection: step 8 scenarios V1 and V2 with the exact console filter. Fallback: step 8b per Open question 3; the plan has no third path form, because a CDS expression annotation cannot reference a singleton from `Products` and a plain `UI.Hidden` `Path` must be a Boolean property of the bound entity (Fiori docs).
- The short path could resolve asymmetrically on the List Report and the Object Page (an unresolved `$Not` binding defaulted to visible on one page and hidden on the other, CHANGELOG 2026-09-16). Detection: V1 and V2 check both pages separately; `RoleAwareActionsJourney` covers the editor side.
- `@assert.target` on `currency` is a behavior change for every client: a draft with an unknown currency can no longer be activated and an import row with a typo in the currency column fails. Detection: the five new tests pin exactly this; the existing fixtures and CSV use only `USD`, `EUR`, `GBP`, so no existing test or seed row is affected (measured, `research/contract-delta.md` section 2).
- If Open question 1 widens the range, the upper edge `9999999999999.99` has 15 significant digits, the limit of SQLite's REAL storage for Decimal; the test then uses a value that round-trips (`1234567890123.45`) and asserts the string. With the recommended bound the risk does not arise.
- Two phases each change the contract; a developer who defers the regeneration turns the sync test red at that phase's gate. Detection: the gate itself (`npm test`), and the per-phase figures in steps 4 and 6.
- Between step 5 and step 6 the two long-path assertions of `test/metadata.test.js` are red by design; both steps belong to phase 3 and its single commit, made only after step 7 is green.
- Mock mode (`npm run start-mock`) is not part of any gate; `mockdata/Permissions.json` keeps serving `/Permissions`, and the short path is the form `sap-fe-mockserver` resolves like any singleton path. `ui-verifier` adds a mock-mode screenshot only if its turn budget allows (not blocking, named in `VERIFICATION.md` if skipped).
- A HANA deployment (not configured) would see a column type change; the ADR-0003 amendment records that no productive data exists, so no migration script is written now.
- `docs/STATE.md` `## Open debt` shrinks by three rows; `docs-keeper` keeps the ADR-0018 shape and does not add narrative there.

## Open questions
1. `@assert.range` of `price`: keep `[0, 99999999.99]` (recommended: the bound is a business rule independent of storage precision, nobody asked for larger prices, 1 EDMX line fewer, no SQLite precision edge) or widen to the type maximum `[0, 9999999999999.99]` (keeps the original "range equals the type" derivation; +1 EDMX line, the test asserts a 13-integer-digit price round-trips).
2. ADR-0003: amend in place with an `## Amendment` section (recommended; precedent ADR-0021 amendments A to D, `Status:` untouched, the other rules stay in force) or write a new `ADR-0024-price-precision.md` that supersedes only the exception sentence (what ADR-0003 line 14 literally asks for; a nearly empty ADR, and the template's `superseded by` status cannot be applied to one sentence of ADR-0003).
3. If step 8 shows the TypeError persists with `/Permissions/isEditor` (or the hidden state breaks): revert to the container-qualified path, close the STATE row as "upstream, no local fix" and keep the LESSONS entry (recommended: no benefit from a contract change that fixes nothing; the long form is the primary documented one and proven in five measurements), or keep the short path when only the TypeError persists but the hidden state holds (not recommended).
4. Two contract regenerations, one in phase 2 (price) and one in phase 3 (path), each with its own figure (recommended: the `/feature` phases and the contract rule), or one regeneration by moving step 5 into phase 2 (`fiori-app-dev` runs in the backend phase, since `cap-backend-dev` must not edit `app/**`; the phase 2 commit then mixes `srv` and `app` scopes).
