# Pattern catalogue: one task, one way

For every recurring task there is exactly one approved way here. An agent that meets a task from the table uses the specified way and example. If the way does not fit, work stops and an ADR is created, not a second way. Links to examples point to the current code; the registry in `docs/registry/` shows what already exists. Rows without an example describe a way that has not been applied in this project yet: the first agent that applies such a pattern adds the example path (and the ADR, if one was needed) to the row in the same change, and the reviewer checks it.

## Data model

| Task | Way | Example | Decision |
|---|---|---|---|
| New entity | `entity X : cuid, managed { ... }` in `db/schema.cds`; projection in the service; labels in `srv/annotations/X.cds`; UI in `app/<app>/annotations/X.cds`; data `cds add data --filter X --records N`, which also merges a facet into the protected `mta.yaml`: the agent reports the `mta.yaml` diff and the orchestrator restores the file before the commit; test `test/<service>.test.js`. Persistence constraints `@assert.unique` live in `db/` (DDL, not semantics; the one exception to "no annotations in `db/`"), for example `@assert.unique.pair` on an assignment entity; every other `@assert.*` stays in `srv/annotations/` | `db/schema.cds` → `Products`; `SubcategoryAttributes` (`@assert.unique.pair`) | ADR-0003, ADR-0026 (decision 1) |
| Code list with selection from a list | Entity `: sap.common.CodeList` with key `code : String(20)`, `UPPER_SNAKE` codes; association from the main entity; value help: see "Value help from a code list" | `db/schema.cds` → `Categories`, association `Products.category` | ADR-0003, ADR-0010 |
| Internal status not chosen by the user | `enum` in the element type, UPPER_SNAKE values | not in code | |
| Monetary amount | `Decimal(15, 2)` + `currency : Currency` + `@Measures.ISOCurrency: currency_code`. | Calculated value | Calculated element `total : Decimal = price * quantity` in the schema; `virtual` + `after READ` only if the expression is impossible in SQL | not in code | |
| Parent-child relationship (document) | `Composition of many Items on items.parent = $self` in the parent, `parent : Association to Parent` in the children. | Typed attribute values | The type lives on the attribute: `DetailAttributes.valueType` (a `CodeList` of `TEXT`, `INTEGER`, `DECIMAL`, `LIST`, `MULTI_LIST`) plus `minValue`, `maxValue`, `scale`; the value row has one typed column per kind (`textValue`, `numberValue : Decimal(15, 3)` for INTEGER and DECIMAL, `listValue` association to a localized list entity per attribute, `selections` composition child for MULTI_LIST). Values are optional. On the client the format, decimals and bounds come from a UI5 type (`sap.ui.model.odata.type.Decimal` with `scale` and `minimum`/`maximum` from the attribute), no hand-written regex; server texts have no placeholders (a constraint passes no arguments). No handler checks values | `ProductDetails` and `DetailAttributes` in `db/schema.cds`, `srv/annotations/ProductDetails.cds` | ADR-0027 (decisions 1, 4) |
| Reference to another entity | `Association to Target` in the singular | `Products.currency` | |

## Service and logic

| Task | Way | Example | Decision |
|---|---|---|---|
| Prevent before validate | Applies to every validation row below. For each rule name the control that makes the mistake impossible before a message is needed (a client type constraint such as `Validation.Minimum`, a dynamic `Common.FieldControl`, a disabled and cleared control, a suggestion list, the currency customizing), or write "none, validation only". Add the control when Fiori Elements offers one without a handler. The server constraint stays the guard on every path (API, import, draft, Save); a control alone is never the rule | the rule catalogue of `docs/features/products-validations/CONTEXT.md` ("Preventing controls") | ADR-0028 (decision 11) |
| Mandatory field | `@mandatory` in `srv/annotations/<Entity>.cds`; an action parameter the same way (`annotate <Service>.<Entity> with actions { <action>(<param> @mandatory) }`): the `Common.FieldControl: #Mandatory` it emits is the only signal Fiori Elements V4 reads to mark a dialog parameter required and to block an empty submit; `not null` (`Nullable="false"`) alone is ignored by the dialog, and for a file parameter the annotation goes on the parameter, not on the stream element of its type. Making an existing field mandatory breaks every writer that omits it: the plan lists every writer (import columns, CSV fixtures, test factories such as `newProduct`, README examples) and changes them in the same phase | `srv/annotations/Products.cds`, `importProducts(file)` | ADR-0004, ADR-0021 (amendment B) |
| Format or range check | `@assert.format`, `@assert.range` in `srv/annotations/<Entity>.cds`; a `before` handler only if it cannot be expressed with an annotation; a rule between two fields: see "Cross-field consistency check". A rule whose default text would not explain the domain reason adds `@assert.format.message: '<KEY>'` or `@assert.range.message: '<KEY>'` (key in `_i18n/messages.properties` and `_ru`); the code stays `ASSERT_FORMAT` / `ASSERT_RANGE`, so the import mapping is unchanged. Open bounds are written `[(0), max]` (`_` is infinity). Fiori Elements V4 (UI5 1.154) ignores `Validation.Exclusive`: it reads only `Validation.Minimum` and `Validation.Maximum`, so an open bound guards the server and the import but prevents nothing on the form. Write a bound the client must enforce closed, at the type's smallest step (`price` `[0.01, 99999999.99]` for `Decimal(15, 2)`) | `Products.stock @assert.range: [0, 1000000]`; `Products.name`, `Products.price`, `Products.imageUrl` with `.message` in `srv/annotations/Products.cds` | ADR-0004, ADR-0028 (decision 1, amendment A) |
| Association target existence check | `@assert.target` | `Products.category`, `Products.currency` | |
| Cross-field consistency check | A rule between fields, including fields reached through an association, is an `@assert: (case when <condition> then '<MESSAGE_KEY>' end)` constraint on the element in `srv/annotations/<Entity>.cds`, key in `_i18n/messages.properties` and `_ru`; no handler. Guard every nullable operand explicitly (`<assoc>.code is not null and <parent>.code is not null and ...`): CQL `!=` treats null as a value. The runtime rejects with 400 (key as `code`, the foreign key as `target`) on active writes, writes a draft message on a draft PATCH and rejects `draftActivate` with target `in/<fk>`; the draft message is written at commit, so it shows on the next `GET`, not in the PATCH response. The constraint is checked at commit, so the row mapping of `importProducts` never sees it: an import column for the field checks the rule per row before the inserts, see "Bulk create from a file". Set membership between a child row and a code list is the same form with `exists <to-many>[... $self.<path>]` (`$self` is the annotated entity inside an infix filter); a duplicate inside a draft tree is `exists <parent>.<children>[<key> = $self.<key> and ID != $self.ID]`, never `@assert.unique` (a violation is a 500 `ERR_SQLITE_ERROR` with `@cap-js/sqlite` and nothing on a draft). Uniqueness a user must see on a draft root is a self-association in `db/schema.cds` (`namesakes : Association to many Products on lower(trim(namesakes.name)) = lower(trim($self.name)) and namesakes.ID != $self.ID`, no annotation) plus `when name is not null and exists namesakes then '<KEY>'`; from a draft it resolves to the active rows, the own active sibling is excluded by `ID`. A rule that reads two fields the user edits ends in `error('<KEY>', <args or null>, ('<field1>', '<field2>'))`: the first target is the message target, the second an `additionalTargets` entry, so both fields turn red and a touch of either one writes the message; targets are string literals of the flattened element names (a foreign key such as `currency_code` is a literal, never a path), arguments may be paths of the annotated row, a localized text as `coalesce(<assoc>.localized.<element>, <assoc>.<element>)`. Inside an infix filter `$self.<element>` is the value of the annotated row (a bound comparison: `exists attribute.subcategories[subcategory.code = $self.product.subcategory.code and $self.numberValue < minValue]`) | `Products.subcategory` in `srv/annotations/Products.cds` (`PRODUCTS_SUBCATEGORY_MISMATCH`); `ProductDetails.attribute` in `srv/annotations/ProductDetails.cds` (`PRODUCTS_DETAIL_ATTRIBUTE_NOT_ASSIGNED`, `PRODUCTS_DETAIL_ATTRIBUTE_DUPLICATE`); `Products.name` (`namesakes`, `PRODUCTS_NAME_DUPLICATE`) and `Products.price` (`error()` with two targets, `PRODUCTS_PRICE_MINOR_UNIT`) in `srv/annotations/Products.cds`; `ProductDetails.numberValue` (bounds per assignment) in `srv/annotations/ProductDetails.cds` | ADR-0024 (decision 2, amendment), ADR-0026 (decision 5), ADR-0028 (decisions 2, 3, 8) |
| Conditionally required field | A field required only while another field has a value is never `@mandatory`: an `@assert` constraint with both targets (`when stock > 0 and (description is null or trim(description) = '') then error('<KEY>', null, ('description', 'stock'))`) in `srv/annotations/<Entity>.cds`, plus `Common.FieldControl: (stock > 0 ? 7 : 3)` on the element in `app/<app>/annotations/<Entity>.cds` (`7` Mandatory marks the field, `3` Optional unmarks it, both editable). The server never evaluates the field control; the constraint is the guard. The import checks it per row, see "Bulk create from a file" | `Products.description` in `srv/annotations/Products.cds` and `app/products/annotations/Products.cds` (feature `products-validations`, R6) | ADR-0028 (decision 4) |

| Dependent field as a control plus guard | When a value of a list attribute decides whether another attribute applies, the value entity names the attribute it enables (`DetailListValues.enables`, backlink `DetailAttributes.enabledBy`). The control: the custom form disables and clears the dependent row while no enabling value is selected in the product and enables it when one is (the user never sees a message). The guard: one branch, marked "guard, not user-facing", `when numberValue is not null and exists attribute.enabledBy and not exists product.details.selections[value.enables.code = $self.attribute.code] then '<KEY>'`.
